## Proposed implementation

`region_pointer.py` is an original stdlib-only Wayland-wire client. It accepts only an owned socket immediately under the owned 0700 `/tmp/screenshot-runtime`, verifies Unix peer PID/UID/GID against the launched Sway process, binds exactly one seat/output and virtual-pointer manager version 2, observes the fresh seat's zero capabilities, and creates a pointer assigned to that seat/output. A roundtrip must then observe POINTER-only capability. It sends absolute pixel-centre motion, real left-button press/release and frame requests. Destroying the virtual pointer must return observed seat capabilities to zero before the connection closes. Requests/events, strings, objects, globals, message sizes, event counts and deadlines have finite bounds; unexpected FDs are closed and refused. No host uinput, physical devices, DRM, privilege, host socket, clipboard or network interface is introduced.

`region_trace.py` parses the exact pinned libwayland debug format from `connection.c`/`wayland-client.c`. The real slurp trace must show POINTER capability, its actual get_pointer request, its `selection` overlay surface, 320×240 configure, matching configure acknowledgement, buffer attach/commit, actual pointer-enter on that same surface at the intended pixel centre, and a cursor/cursor-shape request using the enter serial. The last request is emitted by slurp's enter callback and supplies callback-processing evidence. Discarded events cannot satisfy readiness. Liveness, IPC success, a fixed sleep, an unconfigured surface or an enter on a different surface cannot open the press gate. Unsupported/missing/mismatched evidence causes a bounded failure.

The new executable `region-tools/slurp` wraps **actual `/usr/bin/slurp`** for the unchanged helper's exact `-f '%x,%y %wx%h'` arguments. It sets client protocol tracing only for real slurp, retains its stderr and original stdout in new private files, waits for that process and forwards its stdout bytes unchanged to the helper. It supplies no canned geometry, alternate slurp or screenshot fallback. Signals are forwarded to its owned child; timeout cleanup terminates/reaps that child. The wrapper is staged on the read-only Source mount with mode 0755, avoiding execution from the `/tmp` noexec mount. Original helper/validator bytes remain held.

`region_trial.py` extends the contained software trial with a displayed **test stimulus, not a capture**. The 320×240 image has a single exact 73×59 solid `(18,52,86)` rectangle at `(31,47)` surrounded by `(101,67,33)` and two asymmetric corner landmarks. Real swaybg displays it; its real layer configure/ack/attach/commit trace gates the full-pattern capture. The unchanged helper must capture the displayed frame, and all 76800 actual pixels must equal the independently defined stimulus. A wrong/unready frame fails; there is no fake-image substitute.

After the pointer capability observation, the unchanged helper's region mode runs through the wrapper. The client positions at pixel centre `(31.5,47.5)` and waits for actual slurp readiness, presses, waits for real slurp button receipt, moves to `(103.5,105.5)`, waits for actual slurp motion receipt, then releases. Slurp's pinned integer/inclusive-endpoint logic gives expected actual geometry `31,47 73x59`. The retained **real stdout** must equal that geometry. The helper's new PNG must then pass the unchanged strict PNG validator at 73×59 with every pixel equal to the patch colour. Because the whole patch is exactly the crop size, any translated same-size crop includes contrasting pixels; full-frame validation plus crop dimensions/pixels establish the intended origin. Only the actual helper-produced file is treated as a region capture.

The proposed `run.py` adds one explicit region-stage call after the three held full-colour captures and before the four held refusal cases. Every previous PNG record remains held; the full-pattern and region PNGs are added to preservation checks, and unexpected output/partial entries fail. The original compositor/backgrounds, process limits, runtime/HOME privacy, 196-package inventory, helper/validator, read-only/nonroot/network-none container, CI driver, Containerfile and workflow remain held. The added background/helper are tracked by the existing owned-process mechanism. Pointer destruction/capability retirement, trace records, actual geometry, region result and failures are retained.
