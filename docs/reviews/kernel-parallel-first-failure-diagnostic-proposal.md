# Kernel parallel first-observed failure: bounded diagnostic proposal

This five-copy Source proposal retains the two child exit observations from the poll that first stops the parallel runner, before its existing cleanup runs. It distinguishes an already-observed nonzero acquisition/producer exit from a sibling with no exit observed at that poll. It does not identify the missing acquisition exception or operand, natural exit chronology, or the origin of a later signal. The existing Runner._run_many poll loop stops when both children have returned or either child has a nonzero code. It then cleans both groups before returning CompletedProcess records. The new runtime attribute resets at each call and captures only a two-code tuple at a deciding poll containing a nonzero result. It adds no poll, clock, process, callback, signal, log read/write, timeout, cleanup operation or gate. Both-zero and single-command calls retain no parallel failure tuple.

After run_many returns and the original final exit records are validated/stored, the coordinator copies this optional tuple through a strict public helper. A normal-return failure can therefore retain `parallel_first_failure` alongside the unchanged final producer_exit/acquisition_exit and original BOTH_CHILDREN_EXIT classification. The group has exactly producer and acquisition, each containing a closed kind/code pair. None becomes UNOBSERVED, never NOT_RUN: both children were launched, but this poll did not observe that child's exit. Plain integer codes retain the existing -64..255 range; booleans and malformed tuples refuse optional observation.

For example, a modeled deciding poll `(None,1)` followed by cleanup final codes `(-15,1)` continues to report BOTH_CHILDREN_EXIT. Its new group reports producer UNOBSERVED and acquisition EXIT_NONZERO1. That establishes acquisition was already observed failed at the deciding poll. It does not label the producer signal cleanup-caused in the actual trial, nor establish which child physically exited first when both codes are already nonzero at one poll.

The group is optional on schema4; legacy schema3/schema4 documents remain accepted as before. The public projector refuses the group on PASS, outside first_failed_phase parallel, on partial/extra fields, zero-only/no-observation tuples, NOT_RUN kinds, boolean/out-of-range codes and contradictions with known final codes. A pre-observed code must match its final code when the final record is known. Cancellation after a normal return/capture may retain the group; it cannot promote acceptance or replace first-failure/cleanup authority. Original native PASS rules remain unchanged.

The scope deliberately excludes observation export when run_many itself raises timeout, output-bound, cleanup error or cancellation. Those exception paths remain byte-equivalent apart from resetting/caching the inert runtime tuple and never call the new coordinator observer. This avoids replacing an existing exception/control with a diagnostic failure. Ordinary observer attribute/helper errors omit the optional group; controls when no prior exception is active propagate through the existing coordinator policy. A later serial runtime call resets the tuple, preventing stale reuse. There is no universal exception observer or new private-error parser.
