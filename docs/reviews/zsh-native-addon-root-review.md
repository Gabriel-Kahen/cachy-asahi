## Admission blockers

1. **P1 — Loaded execution state is incompletely bound (`zsh_addon.py:387–426`).** `state`/`verify_loaded` retain function/code/closure/default-tuple identity and selected method bindings, but omit keyword defaults, mutable default contents, non-function imported globals, policy values and property descriptors. Independent controls preserve source files and function identities while changing behavior without refusal. In the actual captured `common` module, replacing its imported `hashlib` binding produces a forged digest on an inert real file while verification passes; replacing its declared `require` function is correctly refused. Synthetic keyword-default, mutable-default and property changes are also accepted. Bind the execution-relevant closed values/dependencies/descriptors, with explicit allowances for legitimate runtime state, before treating this as execution identity proof.

2. **P1 — Mutable decoded source ledgers can supersede the pinned packet (`zsh_addon.py:337–384`, `428–435`).** A control changes the decoded packet rows, paths and retained buffers together with same-size root/view source bytes. `verify()` and `bytes()` accept the replacement bytes while the serialized packet and advertised packet SHA remain unchanged. The object does not compare its current authority ledgers back to immutable state derived from that pinned packet. Preserve and verify the original decoded authority closure; caller-editable maps must not redefine accepted sources.

3. **P1 — Exact class identity does not bind the loader or callback authority (`zsh_addon.py:301–327`, `501–531`, `817–824`).** Independent controls replace a `SourceAuthority` instance's `controller` method and reach actual `run_zsh` output creation without a native callback context, forge `current_controller`/`native_running` directly, and modify `BytesLoader.exec_module` so foreign synthetic code becomes the freshly captured baseline. The output-creation control fails at the later absent contract and invokes no actor; it establishes a bypass of the claimed authority gate, not a native PASS. Authenticate the authority/loader's own source methods, globals and private state, and bind controller custody to the actual callback invocation rather than writable state flags.

4. **P1 — Disposal can stop before KILL after an ordinary signal error (`zsh_addon.py:217–238`).** The cleanup loop catches only `ProcessLookupError` around TERM/KILL. An ordinary TERM error leaves KILL, bounded reap and group-absence proof unattempted and can replace the first timeout/read/control failure. Independent source controls model the child remaining live without sending real signals. Keep the original failure sticky, continue bounded owned disposal where possible, and report uncertain disposal when proof fails.

5. **P1 — A failed revocation write leaves stale PASS receipts and blocks retry (`zsh_addon.py:89–99`, `1018–1033`).** The independent finalization control uses the author's inert receipt-boundary model and the actual `save`, `revoke` and `run_zsh` finalization code on real owned temporary files. A normal late restoration interrupt changes all three records from PASS to FAIL and preserves the exact interrupt. A one-shot `fsync` error during the first revocation instead leaves all three old PASS records, retains `adapter-status/result.json.partial`, and replaces the interrupt with `OSError`. After the injected error ends, a retry fails at `open('xb')` with `FileExistsError`; all three records remain PASS. Make failed temporary writes reviewably recoverable and ensure cancellation/finalization failure makes every public/status selector unavailable or refused even when rewriting fails. This is a source receipt-consistency counterexample; no actual native result or external publication occurred.

6. **P2 — Contradictory CID custody can be reported as clean (`zsh_addon.py:732–737`).** With missing `owned.json` and an existing valid private cidfile, the actual cleanup function returns PASS with `container_submitted: false` and performs no tool binding, typed absence or Docker call. This is an inconsistent-evidence refusal gap: a cidfile alone must never grant removal, but its presence also must not be treated as proof of no submission. Honest-run reachability of that exact artifact shape is unproven; no live container or actor outcome is inferred from the control.
