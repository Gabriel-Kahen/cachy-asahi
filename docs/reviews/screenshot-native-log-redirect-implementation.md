## Changed behavior

The reader separates the three fixed request roles. Run-attempt/job metadata must return200 at their exact configured API URLs and pass the existing identity checks. Attempt-log retrieval must start at the exact configured same-repository/run/attempt API endpoint and receive302. The resulting Location remains an opaque in-memory value; there is no CDN-host or signing-query whitelist, reconstruction, cache or historical fallback. Metadata redirects intentionally fail closed; this supported subset does not implement every general REST redirect behavior.

Every delegated URL must be a bounded absolute ASCII HTTPS DNS URL without control/space/backslash, userinfo including empty forms, or any fragment, and with implicit443 or explicit443. The request target preserves the returned path/query bytes, including escape case and empty query delimiters. At most two redirects are followed, for three requests total. Downstream redirects use the existing finite status set; every target is checked anew. Only the exact initial API request can carry the API token. Follow-up requests use clean explicit headers and no Cookie, Referer, proxy, client certificate or ambient credential handler, even when a delegated URL names api.github.com.

The transport resolves a hostname once, validates every returned address, then connects to a vetted numeric sockaddr. A TCP connection error may select another address from that same finite vetted set, with at most five seconds per TCP attempt and the shared remaining deadline; it does not repeat DNS or an HTTP request. Peer/certificate/TLS failures refuse without fallback. It checks the raw and TLS connected peer and preserves the original hostname for TLS SNI, certificate/hostname validation and HTTP Host. TLS uses an explicit `SSLContext(PROTOCOL_TLS_CLIENT)`, server-authentication default CA loading and assertions for hostname checking/`CERT_REQUIRED`; it avoids the [convenience helper's environment-triggered key logging](https://docs.python.org/3.12/library/ssl.html#ssl.create_default_context). This preserves CA/hostname validation without claiming identical verification flags across Python versions. HTTP automatic connection opening is disabled, preventing a missing socket from falling back to a fresh hostname resolution. Mixed public/private sets, malformed/excessive answers and non-global/special addresses refuse. Conservative explicit exclusions cover relevant older-Python address-classification differences; this is a selected safety subset, not a claim to have independently certified the entire current IANA routing registry. Address classification and peer checks do not prove the physical network route.

## Deadlines and resolver ownership

The existing120-second monotonic acquisition deadline remains. Log retrieval tightens its deadline to the earlier of that deadline and45 seconds from initial Location receipt. Per-operation remaining-time checks and a Linux main-thread alarm cover the parent transport, including slow headers; pre-existing timer/blocked/pending/non-restorable alarm ownership refuses before replacement, and owned timer/handler state is restored on exit.

A signal handler alone does not establish a hard libc resolver timeout: [Python documents that handlers can be deferred while C code runs](https://docs.python.org/3.12/library/signal.html#execution-of-python-signal-handlers). DNS therefore runs in a separate short-lived current-Python worker using literal Source-locked code, isolated interpreter flags, hostname-only arguments, an empty environment and no stdin or unrelated inherited descriptors. It receives no URL, query or token. The worker is capped at32 answers/16KiB of output; the parent waits at most15 seconds or its smaller remaining budget, then owns kill/reap cleanup with a two-second reap wait on failure. SIGALRM is blocked only across worker construction and assignment so pending delivery cannot leave a created worker unowned; the prior mask is restored immediately afterward. No connection proceeds until the returned complete address set passes validation. OS process creation, scheduling and kill/reap latency are not an absolute wall-clock guarantee, and real resolver/transport execution has not been tested here.

Forty-five seconds is a selected local margin, not proof of the server's issuance age or remaining one-minute validity. The reader does not parse signing/expiry parameters or require wall-clock agreement. Timeout, HTTP failure, exhausted redirects or unresolved cleanup fail closed. Root owns selection of any later retry, which must obtain a new Location from the fixed endpoint.
