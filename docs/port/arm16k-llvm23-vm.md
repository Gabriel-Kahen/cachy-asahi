# First LLVM23 private-prefix ARM16K runtime case

The new `scripts/integration/arm16k_llvm23_vm/` implementation provides closed
Source and genuine-input gates, an executable trusted-ALPM guest transaction,
ordinary PAM C/C++ probes, nonce protocol and passive durable ELF/output review.
Old families and shared manifests/workflows remain unchanged. It binds the known
LLVM256 Source365a763bc515a1b3550cc804536ddbf66353aac8 and private-prefix recipe,
while future native package/Run/Job, signature/public TEST receipt, Reader4 result,
Root acceptance, runtime certificate and resource facts remain NULL.

The existing Rust-stage0 journey was read first. It supplies reviewed supervision,
RTC and PAM patterns, but never installs/removes an ALPM package. This new case
therefore uses a separate normal `pacman -U/-R` lifecycle, private Required/
TrustedOnly public-key trust, full baseline payload/metadata/xattr/database and
user preservation, private guest staging, normal removal and durable
cleanup receipts. A PAM builder session runs exact private clang/clang++ versions
and tiny C/exception-C++ programs; actual compiled ELF16K geometry is required,
not inferred from linker flags. Neither111 nor155 is assumed to supply LLVM's
complete driver/ABI/development closure; no extra dependency package is installed.

The Root certificate contract covers complete package-owned namespace/ELFs,
ALPM dependency versions, interpreter/DT_NEEDED/GNU-version providers and actual
loader/CRT/development search. The separate physical plan must account for
compressed staging, expanded payload, raw free space, simultaneous clone/overlay/
readback/log allocations, guest outputs, host memory reserve and whole-actor
readonly quota guard. Numeric limits have no candidate-derived guesses.

**Implementation boundary:** the offline adapter produces only a verified case
packet, never a VM launch. Candidate-specific facts needed for an actual image
preparer and host VM controller/actor binding are still missing. Root must select
and verify the disposable image, exact preparation delta, kernel/tool/credentials,
authority, resource owner, genuine PAM/QMP retirement and complete postboot
preservation before actual execution. The packet explicitly keeps that binding
NULL. This is a completed known gate/guest-contract increment, with outer VM
integration unfinished. README lists exact future command shape and missing inputs.

Only modeled, fenced DATA controls and shell syntax checks ran. No Source export,
GET, lease, Docker, VM, ALPM, compiler, actual Reader or publication occurred. No
LLVM runtime, native16K hardware, M2, performance or release acceptance is claimed.
