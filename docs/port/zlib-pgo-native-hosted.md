# Source-bound hosted PGO construction

This workflow supplies the fresh native producer missing from the earlier
39-file PGO source packet. Under `pgo-source/`, 34 files stay byte/mode-identical.
The active supervisor now uses direct owned-child retirement; four other files
change only to propagate its checksum (recipe policy, PKGBUILD, guest pin and
nested source map). Its instrumentation, deterministic training, source/toolchain/ISA/
path seal, fatal missing-profile policy, independent heldout corpus and inner
two-build correctness gates are unchanged. Prior negative LTO data is preserved;
no benefit is assumed.

Root publishes the complete closed tree and dispatches
`.github/workflows/native-arm-build.yml` on that exact commit/ref with sole input
`source_sha`. The dedicated alias is `.github/workflows/native-arm-zlib-pgo.yml`.
Both render from one template/manifest. Checkout HEAD, input, GITHUB_SHA and
GITHUB_WORKFLOW_SHA must agree. Every source/workflow Git blob and mode is joined
before secrets. No second feature checkout, caller image or caller lock is used.

The lane reuses the accepted original341 producer and exact retained transport:
22 existing private input references, pinned public14 source and retained carrier.
No new credential or acquisition mechanism is introduced. Only new hosted
owned-child/host/receipt controls run, not the original 34 PGO controls.
The helper holds WNOWAIT ownership until final signal and direct waitpid, refuses
ECHILD or lost ownership without further numeric probes/signals, and never uses
Popen wait/poll to establish exit. Docker observations run synchronously in the
main thread. Active zstd inspection uses owned bounded decompression followed by
the unchanged checker's pure-tar parser; its original archive identity is retained.

A fresh signed original341 environment emits its actual owned immutable image
ID and full package inventory. It includes GCC, binutils, make, Python and
makepkg dependencies; actual tool presence/identity remain runtime checks. The
owner checks same-job source/run labels, live daemon image, completed producer
receipt and the complete emitted lock before each candidate. Those values feed
the frozen offline native plan. Synthetic short locks and retired IDs refuse.

Two separate clean versioned-builder containers each train their own profile,
seal it and perform the original two clean optimized builds: two independent
candidate constructions, four profile-use builds total. Inner same-seal payload
equality is mandatory. Cross-candidate payload/archive/seal equality is descriptive;
independent training provenance can differ. The actual daemon inspections retain
fresh container names, readonly source mounts, no cache mount and network none.

All nested `artifacts/pgo-v1-evidence/` data is copied explicitly: raw/decoded
profiles, instrumented programs, training output, seals, inner payloads, effective
flags and transcripts. Each candidate's 234 ordered commands and complete nested
receipt are checked. Public retention is bounded to 512 MiB/20,000 leaves;
ordinary leaves to 16 MiB and libz/package archives to 64 MiB. Each preparation
has an 8,192-leaf limit. Partial failures retain data without qualification.

Pre-run observations identify actual builder consumers. Their absence must be
observed before producer image/tag deletion. Original-group cleanup only proves
no observed live group members; it does not establish zombie/global absence.
Final daemon retirement has separate receipts. The 135-minute job cap exceeds
the 133-minute sum of step caps; cleanup has six minutes.

Root owns publication, dispatch, original acquisition, independent replay and
acceptance. This author task runs no native actor. A future complete receipt is
construction data pending Root review. Installed lifecycle and generic16K remain
separate: the preserved guest gate is present but not run by this workflow.
Physical Asahi/M2, performance, power/thermals and release remain NOT RUN or
NOT GRANTED.
