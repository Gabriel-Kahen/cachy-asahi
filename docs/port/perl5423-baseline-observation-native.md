## What the observer records

After the unchanged fresh signed349 bootstrap and signature/inventory checks,
a separate container runs Python as Root UID/GID0 with every capability dropped,
no new privileges, a read-only root, network none, two CPUs, 512 MiB memory, zero
swap allowance, 64 tasks and a 60-second observation deadline. Its only explicit
mount is the Source at read-only `/inputs`. There is no writable host mount,
volume, tmpfs, device grant, chown or SYS_ADMIN capability. The observer executes
no ALPM command, Perl, signer, network client or subprocess.

The fixed capture includes:

- The exact saved349 lock and current349 package names/versions parsed directly
  from `/var/lib/pacman/local/*/desc`, checked against the saved inventory.
- `/etc/pacman.conf` with its original bytes and exact type, mode, UID and GID.
- Complete maps of `/builder-disabled-hooks`, `/etc/pacman.d/hooks` and
  `/usr/share/libalpm/hooks`, including explicitly absent roots, directories,
  regular-file bytes/hashes and ownership, and symlink targets. Links are never
  followed, including root or ancestor aliases.
- Actual ARM4K credentials, capability sets, NNP, cgroup limits, namespaces,
  mount information and loopback-only interfaces, plus the caller's exact
  Source/ref/run/job/image/token/policy tuple. The coordinator joins the tuple
  to actual immutable image/container inspections.

Original config/hook file bytes are base64 in `file_contents`; their maps carry
SHA256 and sizes. Current package descriptor bytes are retained separately in
`package_database.contents`, with hashes and parsed scalar NAME/VERSION fields
that the DATA validator rejoins to the original bytes. Kernel observations and the fixed
metadata paths are the only reads. No keyring, private key, shadow or home
contents are captured. Aggregate metadata file bytes are capped at 16 MiB,
JSON at 32 MiB, total nodes at 8,192 and each hook-root map at 4,096 nodes.

The coordinator retains original stdout/stderr and ownership receipts, before/
after domain inspections, the original observation JSON, signed bootstrap
evidence and owned container/image absence. Forced cleanup, cancellation,
ownership uncertainty, nonzero/unnatural exit or unknown absence prevents
success. Cleanup targets only the exact Source-labelled owned resources; there
is no broad prune or daemon reconfiguration.

The proposed active native envelope is 5,100 seconds, including a bootstrap cap
of 4,500 seconds and the 60-second observer; cleanup has another 240 seconds.
The native step is 90 minutes and the whole job 120 minutes. Actual resources
and this budget remain subject to the separate external Root admission.
