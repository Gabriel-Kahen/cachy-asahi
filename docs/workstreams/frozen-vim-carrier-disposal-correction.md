## First-cause and close ownership

The old helpers could replace an established cancellation with a later close error and stop attempting remaining directory closes. The new local `frozen_fds` context registers returned descriptors, attempts each close once in reverse order, contains ordinary/control close faults, and preserves the exact first body exception. A cleanup-only failure refuses healthy completion. Finite `frozen-vim-owned-fd-cleanup-outcome-unknown` notes record failed close attempts; pending cleanup cancellation retains the existing frozen_vim_cancelled marker. No blind close retry occurs: a close error can follow a successful close, and the same integer might then name another descriptor.

`frozen_names`, `frozen_directory`, `frozen_read`, copy FDs and the final cache FD use this owner. `frozen_critical` blocks the existing jr.SIGNALS during allocation through descriptor registration/fstat, and restores the prior mask inside the owned scope. Its restoration fault cannot replace an established body cause. Cache/copy retain the existing jr.defer_signals API inside that critical section. A small `frozen_defer` wrapper preserves body cause if handler restoration also fails. Disposal retains fixed four-file bookkeeping; its signal/mask-restoration errors annotate the first copy cause instead of replacing it. Copy/capture/guard still use the same Runner.deadline; no new timer or allowance was added.

The independent first-cause controls were retained as private, source-qualified old/new replays. The old source replaces exact jr.Cancelled with OSError in directory, source read, and final cache close. Directory disposal attempts1 of12 closes. The correction preserves the exact original object in all three and attempts12 of12 directory closes. Separate tests cover ValueError, jr.Cancelled, KeyboardInterrupt and SystemExit as first exceptions across directory/read/enumeration/copy/cache close faults, cleanup-only refusal, a close-before-effect fault, handler/mask restoration, and exact first-cause propagation. Software records uncertain close outcome even when a particular fixture knows it actually closed the FD; no global FD/process absence is inferred.
