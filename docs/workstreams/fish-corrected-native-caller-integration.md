# Fish integration with the corrected native caller

This is a source-only integration proposal for the corrected internal database
publisher. It extends the bounded Fish history package work without changing
the primary package inventory, workflow, platform stack or Git. The current
roadmap and outline require the complete R1–R5 port and M5–M9 acceptance; this
proposal contributes to repository, shell and lifecycle work and does not
complete those milestones.

Two independently materialized job source closures use identical six-file
common caller code. `topmem-v1` retains the original eighteen-member addon;
`fish-history-v1` selects the new twenty-four-member Fish addon. Both retain
Source96 byte for byte. Caller schema2 binds a fixed profile through the CLI,
manifest, configuration, child report, admission and retained public result.
The original eight builds, four comparisons and 249 signature observations
stay separate from each addon’s four builds, two comparisons, six signature
observations, one lifecycle and two database productions. Their private
namespaces, TEST key paths, repositories, labels and journals are distinct.

The producer supports two closed package profiles. Fish requires its exact
seven payload hashes/modes and package metadata, including `fish>=4.0`, its
original-helper optional dependency, MIT licensing, `any` package architecture
and the two fixed versions. Topmem’s default package and database behavior is
covered by byte and journal equivalence controls. An architecture declaration
does not establish a successful ARM build.

The V2 policy selects GPG and its agent plus their explicit helper/linkage
closure. Repository databases are produced internally; host `repo-add` is not
used. The legacy `repo_add_sha256` owner field explicitly binds the selected
internal producer source under this V2 policy. Exactly fourteen GPG journal
entries, two database-production records and twenty-one repository files are
required. The caller regenerates database bytes from the actual package and
signature bytes and checks aliases before and after lifecycle, while holding
the existing file custody checks. Regeneration alone is not signature proof;
all six selected cryptographic verification observations remain required.

The Fish engine exposes a fixed publisher context and package-reader adapter
seam. Its closure does not accept publication through an unrelated namespace
attribute. A missing publisher, database admission callback or lifecycle
bridge refuses before addon allocation or builds, after the baseline identity
gate. Callback results require an exact integer database count of two.

The child validates its prepared signer journal, nodes, socket identity and
agent before registering that socket with a nested instance of the existing
owned Runtime. Its deadline is exactly the inherited work cutoff. A fixed
service repeats policy and signer custody checks during the lifecycle. This
reuses the existing clock, environment, runtime and recovery sequence.

The future Fish probe and container entry remain byte-identical to the prior
sealed proposal. Pacman already consumes the signed `fish-history` database
through the owned `file:///repo/v1` and `v2` configuration. All seven phase
receipts, ninety-seven CLI/PTY cases and forty-seven progress records remain
required, including protected user-file UID/GID and content conservation,
natural returns, cancellation and no Enter on expanded buffers.

Recovery uses the selected source union, exact engine command/mount metadata
and the same owned broker, journal and absence predicates. A peer found that
the first recovery draft expected a different original-helper mount path from
the engine. The original draft and causal refusal/acceptance control are
retained; a separate correction selects the engine’s actual destination.
All results remain provisional until signer, addon and baseline recovery,
owned-image absence and successful outer Runtime close.

Artifacts are under
`artifacts/reviews/fish-corrected-native-caller-integration-proposal-20261013/`.
`jobs/topmem/closure.json` and `jobs/fish/closure.json` list the proposed exact
source files, manifests and proof counts. Their tool-policy shapes contain
explicit unselected placeholders; they are not execution grants. Root must
select actual ARM tool/helper/library metadata, a committed source revision
and the existing clock, independently review the combined source, then run
the two native jobs. Source checks and inert causal tests do not establish
actual socket/runtime service behavior, signing, database ingestion,
installation, native reproducibility or M2 hardware compatibility.
