## Capability validation before publication

Before selecting any owner result/events/logs or frames, the receiver reads the bounded owner JSON, computes bounded cleanup metadata, and validates the optional pair **qemu_capabilities / qemu_capabilities_sha256**. Presence must be symmetric. It authenticates captured run.py bytes against the contract's trusted CORE digest, parses AST, extracts only three literal constants and the exact unannotated/no-default/no-decorator one-argument capability_projection function, and compiles that captured function into a minimal namespace. No owner import, bare common import, module top-level code, decorator/default/annotation expression or arbitrary constant call executes. The supported 128*1024 limit expression is evaluated only as multiplication of two literal integers. Missing/ambiguous/executing declarations or source drift refuse.

This reuses the producer's exact closed validator rather than maintaining another schema. Rows are a bounded ordered prefix of version/tcg/virt-machine/virtio-gpu-pci; exact keys, statuses, closed reasons, nonboolean return codes/sizes and null unobserved-output semantics are preserved. Unknown strings, nested objects/raw stream fields, types, partial rows, wrong order/duplicate checks and excessive output sizes refuse before copying. Source schema is documented in the owner workstream. Canonical hash is SHA256 of UTF-8 `json.dumps(rows, sort_keys=True, indent=2) + "\n"` from the captured validated list; raw JSON formatting is not part of its ABI. A missing half, malformed hash, noncanonical serialization hash or changed body refuses.

**All four capability records must be PASS before any guest/frame CAPTURED/PASS claim or successful boot/GBM/frame/phase/guest event can be published.** The check runs before creation of public selections; a malformed or incomplete success receipt cannot first escape as apparently accepted public JSON. Complete capability preflight alone grants no guest acceptance: all existing source/image/contract identities, exact five owned cleanup records, event protocol/hash, session/frame proof and frame bytes must still pass. The result remains CAPTURED_REQUIRES_VISUAL_REVIEW; independent visual review and hardware/performance remain open.

A valid partial STARTING/FAIL list, including null stream observations for cancellation or launch failure, is retained only when the owner reports failure and has no success/frame/events claim. A failed receipt with both new fields absent remains diagnostic-compatible; it still requires the corrected21 preflight and can never pass or publish frames. Earlier failed run38237127237 is preserved historically, not reinterpreted as corrected execution. Receipt failures use fixed qemu-capability-source-refused, qemu-capability-record-refused, qemu-capability-binding-refused or qemu-capability-success-required codes; source/exception/help text never enters adapter diagnostics.
