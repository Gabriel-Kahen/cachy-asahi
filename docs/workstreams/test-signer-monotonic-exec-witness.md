# TEST signer monotonic execution witness

A new conditional software mechanism is implemented as an original filter generator, a pure controller and a freestanding aarch64 launcher Source. It advances beyond the prior unchanged-Source refusal, but **is not an integrated signer fix or a proven native mechanism**. The controller can derive an execution-image proof from a verified first FD exec and an immutable no-later-exec invariant; it never fills a `/proc/exe` row with an intended value. The existing signer, shared manifests and workflow remain unchanged.

The kernel premise is pinned to Linux v6.12 commit `adc218676eef25575469234709c2d87185ca223a`. Ten distinct primary texts are retained by content hash (213,126 bytes total), with one additional failed lookup, within the 12-text/6-MiB scope. Runtime hosted-kernel equivalence remains unestablished. The preserved actual Topmem03 failure remains errno13 at executable readlink, recovery uncertain and absence unproved; no historical agent was contacted or cleaned up.

## Mechanism and successful-exec witness

The proposed static launcher receives exactly one held, root-owned, policy-hashed gpg-agent ELF descriptor at FD197, the inherited agent socket at FD194 and an exclusive parent transfer channel at FD196. The shim itself must also be launched from a held, Source-admitted compiled ELF descriptor; a mutable pathname or a build command alone is not that admission. Parent/native admission must prove these descriptors refer to the selected objects and bind the executable's inode/bytes to the exact Source, policy, nonce, job/keyhome/socket inode records and fresh generation. The shim does not reopen the executable pathname. Its initial agent argv and sanitized environment retain the existing supervised, no-autostart-scdaemon, loopback and no-external-cache choices.

Before its final execveat, the shim sets no_new_privs and installs the exact filter with NEW_LISTENER. It sends the listener via SCM_RIGHTS with the nonce, then closes its local listener and transfer descriptors. Parent receipt must authenticate kernel SCM_CREDENTIALS, exact message length, a single rights descriptor, no truncation and the one owned Popen child. Credentials from socketpair creation alone are insufficient. Only the parent retains the listener; it is not handed to the agent, serialized or published.

The 38-instruction filter uses the exact little-endian aarch64 ABI. It notifies only reserved-FD execveat with AT_EMPTY_PATH and the brk syscall. It denies other exec, every clone/clone3 (including threads), new filters, specified process/namespace/metadata/listener-duplication bypasses and async io_uring setup. Bad architecture kills the process. PR_SET_DUMPABLE(0) remains allowed, preserving hardening; enabling dumpability is denied. Missing notifier produces a failed syscall rather than permission to exec. Compatibility with the selected GPG agent's thread/syscall needs is **NOT RUN**; refusal must remain a failure. `filter/README.md` states the precise policy and trust limits.

One initial execveat may be continued after held-FD/launcher/notification/birth custody checks. CONTINUE is only permission to attempt exec. CLOEXEC closure, notification retirement and a live pidfd do not prove successful exec. The pinned exec Source closes CLOEXEC descriptors before final completion and permits later fatal failure. [Linux exec Source](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/fs/exec.c)

The proposed stronger witness is a suspended brk syscall after that single initial continuation. After filter installation the original static shim issues only raw sendmsg, close, execveat and exit_group; all failed-exec return paths go to exit_group, and it has no brk syscall, libc/allocator, thread or user signal-handler path. A brk **instruction** in its fatal fallback is a trap, not the brk syscall. The controller requires a fresh notification from the owned PID with valid ID before and after a real exact stat/status/cmdline observation, and a nonterminated bound pidfd. Under the audited compiled-shim and ELF-handler premises, this proves return to user mode in the selected new image. Neither intended argv nor raw EOF grants this state.

After the witness, the parent refuses every subsequent execveat notification, even if the agent reuses FD197. Other exec entries are denied in BPF; filter stacking and PR_SET_MM image/argument metadata rewriting are blocked. All process creation is denied. Kernel filters survive exec and cannot be removed; the trusted parent never transfers its listener or grants a second continuation. This supplies the conditional monotonic-image invariant. The UAPI warns that CONTINUE with mutable pointer arguments is unsafe as a generic security policy; here only the one single-thread, no-fork, Source-admitted static shim may receive it for exec, with held FD and immutable instruction/data provenance. External privileged mutation remains outside the existing trusted-kernel/controller/root scope. [Seccomp UAPI](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/include/uapi/linux/seccomp.h)

At every existing binding, prepare, before/after-command, prepared-custody and recovery guard, the runtime adapter must still observe exact current argv, all four UID/GID values, start tick, process group/session and live state. Missing/inaccessible command line or mismatched observations refuse. Source, tool/library policy and job/keyhome/socket inode custody are rechecked. The typed `MONOTONIC_EXEC_WITNESS_V1` proof carries the first verified executable provenance and active kernel invariant; it is a separate proof kind, not an invented executable observation.

## Birth and controller state

The initial exec notification also provides a narrow race-safe birth interval. The native bridge must perform, without a reply between steps: ID_VALID for that notification, pidfd_open for the owned Popen PID, then ID_VALID for the **same** notification again. Pinned seccomp Source removes the pending request under its mutex before an interrupted task can leave the notifier; ID_VALID requires SENT under that mutex. Thus the second successful check proves the original task remained pending and its PID was unrecycled during acquisition. A failed second check leaves the fd potentially foreign: close it without signals and retain uncertainty. No default signal handler, SIGCHLD reset or clone3 availability assumption is needed. The confirmed local Source audit gives exact line ranges. [Kernel notification implementation](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/kernel/seccomp.c)

`source/witness.py` implements the finite transition controller. Listener and pidfd are exclusive opaque object tokens, not file/JSON attestations. It binds nonce/generation, closed notification identity, one initial attempt, actual argv observations and original absolute endpoints. No image proof exists after CONTINUE alone. Caught corruption permanently removes transition authority; duplicate birth acquisition is refused. Cancellation and work expiry preserve first cause/sticky uncertainty while a still-valid proof may authorize the remaining reserved cleanup. No endpoint is reset and clock rewind is refused. Listener close failure cannot produce absence. Its termination result can report only exact owned task termination with matching pidfd; it deliberately reports neither keyhome absence nor signer-recovery PASS. Existing custody/removal/journal guards must supply those separate results.

## Source and inert verification status

`source/witness_shim.c` and `exec_filter.inc` are reviewable, original MIT Source. The shim is uncompiled. Proposed build flags are `-O2 -ffreestanding -fno-builtin -fno-stack-protector -fno-pie -fno-tree-loop-distribute-patterns -nostdlib -static -Wl,-e,_start,--build-id=none`; compiler identity, target, flags and actual binary result require Root's bounded native stage. Static ABI assertions must pass. That stage must inspect the exact resulting ELF and post-filter syscall paths for compiler-generated helpers/handlers/allocations and pin its bytes/inode. C text checks cannot establish those properties.

The filter's four pure groups passed 202 direct assertions and 1,503 independent symbolic comparisons. The generated FD197 program is 304 bytes, SHA256 `39f5f7faa1eb0f12635c0f015b09176f50b2570121dc6179fd3140024f0343e9`. The first less restrictive output is preserved separately.

Six controller control groups passed 107 assertions. They cover causal event ordering, proof/custody corruption, birth validation/replay, real-observation requirements, cancellation/deadlines/closure and the shim's Source failure paths. All native premises in these fixtures are explicitly synthetic. A caught failed-birth-validation schedule initially acquired a new token despite corrupted integrity; the controller now applies its central work gate to acquisition and rejects duplicate acquisition. The failing attempt and corrected outcomes are retained. These controls do not establish native success, executable inode provenance, compatibility or actor cleanup.

## Concrete remaining proof and integration work

The mechanism requires these bounded software deliverables before native signer adoption:

- Authenticate the hosted kernel's relevant seccomp/exec semantics and supported UAPI. Match or separately audit its differences from the pinned Source. Prove native ELF handler selection, including absence of an overlapping binfmt_misc/other handler that substitutes another executable; verify the selected interpreter/library closure. An ELF header alone is insufficient.
- Admit and compile the exact static shim through a separately pinned Source-built executable grant. Keep the existing 20-row GPG/helper policy intact; do not insert a guessed binary hash or broaden its accepted paths. The compiler/build provenance and new binary descriptor need their own explicit proof. No new binary hash is supplied here.
- Implement the small native adapter for exclusive SCM_RIGHTS/SCM_CREDENTIALS receipt, seccomp ID validation/response, double-validation pidfd acquisition and bounded event service. Runtime syscall responses must come from owner-held kernel objects, not the pure model's boolean fixtures. ioctl RECV can wait even after a readiness race, so a poll alone is not a deadline proof; the adapter must prove bounded interruption/service without new clocks or foreign signals.
- Integrate the typed image-proof branch into signing.start, prepare, each command guard, prepared_custody and recover. The addon child and parent need an authenticated, generation-bound way to query the parent-held witness; a persisted JSON snapshot is not an active witness. Preserve first failure/cancel behavior, all owner/journal and socket/keyhome guards, and fail-closed recovery. This parent/child bridge is not implemented here.

`source-registration-plan.json` names the exact proposal rows and the two profile cascades. Existing Topmem/Fish manifest pins are retained as inputs. Future adoption must update the shared caller/signing boundary, exact member allowlists and new Source/compiled-shim grant together, rederive both full Source/policy/workflow proofs, and bind each actual new Source separately. Future counts and binary/commit hashes are left unset until the exact integration exists. No shared Source or external variable was changed.

## Short Root native probe contract

After peer adoption of the Source and native adapter, select one signer-only probe with one original work endpoint and a reserved cleanup endpoint. First authenticate Source, existing tool policy, compiler/shim grant, kernel/handler scope and native ABI. Use one fresh Source-bound job/keyhome/socket/nonce generation; launch only the shim and agent, without key generation, addon commands or baseline package builds. Prove listener handoff, double-validation birth, first continuation, suspended post-exec witness and exact argv/credentials/session; then invoke the same current-image guard before unconditional owned-task termination and existing keyhome/socket cleanup. Unsupported ABI, missing brk witness, thread creation refusal, failed observations or any uncertain cleanup must remain FAIL.

Bounded negative probe selections should cover failed initial exec (no image proof), denied second exec, invalidated initial notification (no pidfd signal authority) and cancellation during a pending witness. Do not run a generalized matrix or repeat baseline8 builds. Retain only closed Source-bound stage/result/operation/errno, custody and termination/removal outcomes; no raw keys, handler/clock values, notification pointers or agent output. Probe success is not full addon acceptance, installed behavior or release admission. Root alone owns dispatch and actual actors.

No FFI, seccomp installation, process, proc, GPG, signal, socket, library or native-build actor ran in this turn. The full R1–R5/M5–M9 objective remains active and unfinished; this is software mechanism progress with explicit integration/native proof gaps.
