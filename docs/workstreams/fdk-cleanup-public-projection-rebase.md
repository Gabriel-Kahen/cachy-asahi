## Snapshot contract and custody

The outer public `status.json` may include exactly `producer_cleanup: {"availability":"UNOBSERVED","observation":null}` or an `OBSERVED` envelope containing the diagnostic's strict eleven fields: schema version, scope, phase, call, journal, reason, boundary error, observation error, status, absence verified and cancellation. Plain scalar types, exact keys and finite existing enums are enforced. Legacy omission is accepted. Invalid private observations become UNOBSERVED; malformed present public fields are refused.

The controller and workflow share the same two pure schema-helper ASTs. Business status excluding the optional projection is still the existing `evidence.public_status(report)` result. No source, signature, producer, worker, PASS, cleanup or cancellation predicate depends on the projection: fabricated optional PASS cannot promote authoritative failure, and failed or invalid optional data cannot veto otherwise valid business PASS.

The controller enables a read window immediately before the existing producer runner call, after the complete source gate. That window is not proof a process launched. The fixed run-owned `producer-worker.json` is captured at most once, with a 65,536-byte bound, regular-file/owner/mode-0600/single-link checks and stable before/after identity. Duplicate JSON keys, nonfinite values, extra credentials, raw paths/errors, oversized data and inode replacement are refused. The private digest is retained; the public observation is detached. Later file creation, replacement or caller mutation cannot change the snapshot.

Ordinary optional-reader faults preserve the business failure cause. Cancellation propagates through the existing late-failure rewrite; the attempted marker prevents rereading. Source failure cannot promote a preexisting diagnostic. The two added observer-fault controls use the corrected earlier proposal's valid inert fixture arguments and assert actual injection, avoiding the earlier vacuous fixture setup.

`ABSENT` describes journal metadata. A durable default `not-run` describes the last observed snapshot. Neither establishes container absence, no cleanup attempt, no process launch or reaping. The carrier retains its reviewed finite limitations: an arbitrary replacement open hiding its returned descriptor cannot be recovered; ambiguous close is not blindly retried; an `fstat` failure may leave unaccepted private cache material. Compilation or modeled scheduling cannot establish hostile-interleaving, hardware or cleanup guarantees.
