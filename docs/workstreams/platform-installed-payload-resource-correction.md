# Installed-payload resource correction: source-only handoff

This corrects the remaining core descriptor-disposal and reader child/pipe-disposal and combined-ledger findings. It is a source/model candidate. Root review and a new independent parent peer are required before extending actual image observation. No image, debugfs, device-content, GPG, network, native-build or installation actor ran for this correction.

The owned change is limited to the four core/reader source and test files, this new guide, and `artifacts/reviews/platform-installed-payload-resource-correction-20261012/`. Shared inventories, workflows, other package lanes, Git state and previous held packets remain outside the change.

## Concrete corrections

The core's `close_owned` helper masks SIGINT, SIGTERM and SIGALRM during finite disposal, attempts every owned descriptor close after a close fault, restores the caller's mask and preserves an initiating exception. `readable_at` disposes the readable FD and its O_PATH binding through that helper; held ancestor loops use it too. A cleanup-only failure still refuses the operation. This is Linux O_PATH/proc-fd behavior, not a portable or physical-device validation claim. One attempted close per owned FD cannot prove that an arbitrary failing close released the OS descriptor.

The reader protects tracked process cleanup with the same three-signal disposal window. A failed poll, termination or wait does not skip subsequent bounded reap attempts or either pipe close. Both closes are attempted even after the first fails. The first business/cancellation cause remains primary, and a secondary cleanup failure is attached as an exception note. Restoring the old mask may deliver a queued cancellation; that cannot return an accepted comparison. The existing two-second cleanup reserve, clipped twenty-second call and absolute caller cutoff are retained. Fault models establish attempted custody and no-result behavior; they do not establish absence of real child processes.

`WorkLedger(source, deadline)` captures the exact SHA-pinned core once and creates one Budget. Archive decoding uses `ledger.archive_nodes(ref, package_tuple)` and installed observation must use the same ledger through `open_selected(..., ledger=ledger)` or `run_selected(..., ledger=ledger)`. Default actor selection still refuses before input I/O. Explicitly selected calls missing the ledger refuse too. The selected entry point uses the ledger's captured core and validates the same source path, source pin and exact absolute cutoff; it does not create a new Budget.

Each active archive or Tool has an exclusive lease. Sequential Tool retries retain decoded bytes, nodes and prior installed stdout; a released Tool cannot make another call or reacquire its retired lease. Retired owner identities are retained to prevent identity reuse, with a separate finite maximum of 500,000 leases per ledger. The ledger also retains the existing `3 * 500,000 + 2` process-call limit across fresh leases. Each selected process attempt consumes that global authority before the factory can run, including failed captures. `Tool.calls` remains a local diagnostic and cannot renew the global limit. The ledger rejects Budget replacement, cutoff changes, counter type errors and counter regression, including global calls. Its high-water marks are internal custody checks, not authentication of facts supplied by an adversarial Python caller. The caller must retain this ledger for the entire correspondence job; starting a new job explicitly creates a new ledger, so this API is not a persistent cross-process quota service.

Every stdout chunk is charged to shared `tree_bytes` before local size, diagnostic, return-code or post-read deadline refusal. Failed captures therefore retain their debt. `Tool.output_bytes` reports local work and has no cap authority. Archive `Counted.read` also includes prior `tree_bytes` when clamping its decoded read, retains the one-byte refusal sentinel and charges failed overshoot. The combined cap works in both phase orders without allocating cap-sized fixtures.

## Bounds and retained behavior

The combined decoded/archive plus installed stdout cap remains 8 GiB, regular-file cap 512 MiB, metadata stdout 8 MiB, stderr 64 KiB and read chunk 1 MiB. Symlink target retention remains at most 4,096 bytes, node budget 500,000, depth 64, report cap 256 MiB and caller cutoff at most twenty minutes. Archive-specific compressed/decoded/member limits remain. Reference and tool/image digest hashing remain separately bounded input validation rather than decoded-work charges.

Source mode/type/hash checks, no import/PYC fallback, no-follow metadata-first opens, pinned identities/ancestors, inode-only debugfs command grammar, typed listing/stat parsers, raw stat hashes, special-node no-cat policy, full rechecks, final input rehash and result withholding remain. The earlier four corrections stay in force: ordinary-type validation before readable open, deadline checks through hardlink work, implicit-root symlink resolution and finite repeated symlink traversal. The retained tool-contract and image pins are unchanged; the reader binds the final corrected core SHA explicitly.
