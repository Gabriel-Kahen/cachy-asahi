## Finalization behavior

The wrapper retains a direct reference to the exact first exception, then re-raises it through the existing exception path. Final process polling/stopping and receipt publication each catch ordinary and fatal `BaseException` failures separately. A secondary cleanup or receipt failure cannot replace an established business refusal, cancellation, or fatal first exception.

If execution did not already raise, a final cleanup exception refuses the operation. If cleanup succeeds and receipt publication fails, that exact publication exception refuses the operation. A pending zero child return cannot escape a failed finalization. If cleanup and publication both fail without an earlier exception, the earlier cleanup exception wins. No new success or public admission grant is created.

The stop sequence and publication are each attempted at most once. A receipt-write failure triggers one best-effort unlink of the receipt name in the freshly created owned job. A disposal failure is suppressed so it cannot replace an established first cause or the publication refusal. A write that completed before reporting failure is still unaccepted. When unlink also fails, bytes may remain; **disposal is not attested**. Root must require the successful wrapper/guard outcome as well as its bound receipt. A receipt file alone cannot establish acceptance after a failed wrapper invocation.

The correction preserves the same child commands, signature checks, native source `a8b6ed8971a38089a4499dcec605477c4e48d7a47c3de485d205f6a44678b898`, 79-file build closure, historical locks, selected successor lock, and 5,400-second actor ceiling with the existing bounded stop sequence.
