# Maintained native official prefetch proposal

This is a separate proposed executable lane for the maintained Vim 9.2.1178-1 successor. Source review and finite models are preparation evidence. Official fetching, Git actors, GPG, Docker, compilation, installation and M2 hardware checks were not run for this proposal. The guarded-build predecessor remains sealed and unchanged.

## One clock and the inherited guard

The first workflow step records and hashes an owned 0600 clock inside a fresh 0700 directory, before checkout. All phase runners use its monotonic times and matching workflow/source commit and run context. The 7,200-second total includes checkout, source proof, setup, official fetching, guarded native work, recovery and metadata retention. The proof ends no later than start+300 seconds. Prefetch ends no later than start+1,800 seconds. Guard work ends at the original total cutoff minus 120 seconds; metadata uses the remaining total cutoff. These are absolute times, not new budgets. The native workflow's 118-minute step timeout is only an outer interruption cap.

Source proof uses the captured owned runner to compare all 96 files plus the packet against committed Git bytes and modes. It disables Git replacement objects and global/system configuration, hooks, fsmonitor and optional locks. The proof receipt binds the exact packet, clock and source/workflow commit. Each subsequent phase rechecks the source packet. A source packet and proposed workflow must still be registered in one committed Root revision before this proof can succeed.

The helper's child runs under the inherited KSM process group and storage envelope, inside its fixed prefetch scope. Actual natural exit zero, runner exit zero and completed reaping are required, followed by a typed exact 501-pass/zero-fail/zero-pending receipt and positive final cache verification. Socket checks bound individual I/O; the parent process cutoff is the whole-phase backstop, including slow header reads. Interrupted, timed-out, missing or late receipts cannot authorize the native phase.

The native guard accepts only this exact local cache, rehashes all 501 files and independently verifies all 249 GPG signatures before building. Its network fallback stays denied. It preserves the inventory341, eight builds, four byte comparisons, provenance and owned-container cleanup requirements of the predecessor. The inherited controller reserves 360 seconds within its guard cutoff; single recovery remains capped at 180 seconds. Publication is bounded metadata after recovery and before cutoff. Signing is not performed by prefetch; a hash-matched downloaded input alone does not satisfy signature admission.

## Storage and evidence limits

Fresh cache directories are owned 0700; generated files are 0600, single-link regular files. Held directory and file identities, exact membership, sizes and hashes are checked. The preserved native rename is path-based in an exclusively owned cooperative namespace. These checks are not a defense against a malicious same-UID actor changing a path concurrently. The inherited 16 GiB / 8,192-node / depth16 periodic storage envelope, 8 GiB free reserve and process/file limits remain observation and refusal controls, not an enforcing disk quota or proof of daemon-cache disposal.

Retention runs on success or failure without requiring successful proof/prefetch. It exports only closed status/count fields and raw receipt hashes; acquisition signatures remain explicitly NOT RUN until the native guard. The native metadata helper retains its closed publication grammar. Payloads, key homes, unrestricted private JSON and raw private command errors are excluded. A failed metadata phase does not become a successful native checkpoint. Cancellation or an expired global clock can leave retention unobserved and therefore unavailable.
