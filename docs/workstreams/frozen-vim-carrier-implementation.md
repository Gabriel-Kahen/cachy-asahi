## Minimal controller contract

The existing CLI gains `--frozen-vim-carrier PATH` and optional `--frozen-vim-manifest-sha256 SHA256`. Omitting both preserves the original route. A pin without a carrier, bad types/pins and lexical overlap refuse before creating output or inspecting carrier content. The original fresh external job-output refusal remains first in the execution route. Carrier contents are read only after complete packet/source/Git verification, authenticated worker-validator capture and recorded native-source hash; the hook runs before broker construction or producer launch.

The helper derives an immutable `FrozenVimInputs` from the captured original input lock at `packet.INPUTS_SHA`. It cross-checks the four literal original names, integer lengths and full SHA256 values against the source-defined production tuple, including both signatures. A rehashed arbitrary lock cannot choose other payloads. The original total is 9,790,183 bytes. The optional manifest pin binds canonical UTF-8 JSON with no trailing newline: `{"inputs_sha256": <frozen input-lock SHA>, "files": [{"filename", "size", "sha256"}, ...]}`; rows are in lexical filename order and JSON keys sorted with compact separators. This manifest contains no endpoint, URL selection, source-pass flag or execution grant. The exact canonical bytes and digest are retained in the review artifacts.

The controller also retains a private receipt with the source commit and actual run/attempt strings. Existing hosted commit/Git/source checks run first; carrier mode additionally requires finite positive decimal run/attempt identities. Root's reviewed workflow/transport and retained retrieval/retention evidence select and authenticate the external carrier provenance. Parsing a label or passing a matching manifest hash supplies no endpoint, signer, license or native authority.

## File custody, time and failure behavior

The carrier must be a separate real directory outside and non-overlapping with checkout and fresh job output, owned by the ordinary user, mode 0500 or 0700. Every parent is opened with no-follow directory FDs and remains bound to its lexical inode/owner/mode. A bounded directory selector sees at most four members plus one refusal entry; it never scans or restores a whole existing cache. Exactly the four selected raw files must exist. Files are owned regular single-link nodes, safe non-executable modes, exact sizes/full hashes, with stable path/open-FD metadata. Symlinks, hardlinks, FIFOs, missing/extra members and changed parents/files refuse.

All four objects are captured and verified before creating `<output>/private/cache`. The cache must be fresh; it is mode 0700, with exclusive no-follow mode 0600 file creation. Copies use only captured immutable bytes, bounded 64 KiB reads/writes, full destination reread/hash/size checks and created-inode correspondence. Source/carrier/parent and previously completed destination stamps are checked through each copy. Source drift, same-byte foreign-inode substitution and late completed-file drift refuse.

Every capture/copy/guard receives the existing absolute `Runner.deadline`, selected by the existing default 7,200-second controller allowance. No new allowance or timer is selected; producer 3,300 / FDK 3,000 defaults and original acceptance remain unchanged. On failure or cancellation, fixed four-file disposal removes only this helper's created inodes from its still-bound owned directory. This finite actor-free bookkeeping can run after copy expiry; it creates no new copy/producer allowance and claims no hard real-time guarantee. Foreign cache/directory/file substitution, unknown members or disposal errors cause cleanup refusal rather than foreign deletion. The original exception remains authoritative with a finite disposal-failure note. Deferred disposal cancellation propagates into the existing cancelled FAIL state without masking the first copy error. A refused/displaced cache can remain as private failure evidence; the broker/producer is never launched after helper failure.

No original package/archive is repacked, executed or publicly exported. `native_arm.fetch` is byte-identical and retains its valid-existing fast path. Its own full size/hash check still runs. All 501 original acquisition objects and all 249 signed-payload crypto/authorization checks remain mandatory before image/recipe/native acceptance. Hash-pinned signatures alone establish no crypto PASS.
