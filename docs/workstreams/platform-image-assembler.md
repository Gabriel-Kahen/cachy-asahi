## Executable behavior

`prepare()` checks a complete declared package selection and each exact tuple. Prepared file bodies must match their node length/hash/mode/UID/GID; control/scriptlet entries, special nodes and undeclared file bodies are refused. Shared paths are permitted only for identical directories. Every parent must be an explicit directory; symlink or regular-file parents are refused. Hardlinks require a direct regular target within the same package with matching inode metadata. These operations reuse the pinned project's `path`, `package_identity`, `node_shape` and `resolve_link` helpers from `scripts/platform/installed_payload_correspondence.py`, captured with SHA256 `3a71ba896700f72130e35a56845516bd9c42de0b1b0fd782b79829b37ac262a7`. Archive readers and runtime actors from that source are not called.

`configure()` applies only the internally pinned recipe catalog. It checks exact preimages, logical package ownership, preserved factory nodes, directory metadata, new-path absence and a single writer for every configured path. It operates on a separate copy after the immutable pristine projection. No shell/source recipe is evaluated. A recipe with altered content, source hash, ownership, preservation policy or output metadata fails. There is no resolver fallback or historical-image import.

`emit_bundle()` streams a PAX tar with fixed epoch, stable ordering and explicit modes/UID/GID, blank owner names and deterministic link ordering. `rootfs/` contains payload/config nodes; `metadata/assembly.json` is separate project metadata and is not an installed rootfs file. The output manifest records original package nodes, declared archive/source references, config before/after deltas, newly created project directories, output ownership and unresolved runtime links. Input references are declared prepared-map provenance, not fresh package/signature authentication. The caller owns the output stream; no host path is extracted, followed or modified by this API. Whole prepared byte maps remain in memory, so production resource sizing/streaming intake is still required.

`compare_builds()` compares complete returned manifests and bundle digest/size records. The executed tests independently rehash and compare the two owned output byte streams. This API does not authenticate a later externally modified output solely from caller-supplied records.
