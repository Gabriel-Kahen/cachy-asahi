## Concrete phase order

1. Before checkout, the trusted launcher receives the Root-selected envelope/peer bytes and literal pins from reviewed external bootstrap custody. Those bytes must already be available; fetching or deriving them from an arbitrary checkout is not implemented here. It captures a monotonic preparation entry and calls `prepare(..., preparation_deadline=entry+60)`. The constructor refuses a deadline later than its own entry+60. This finite preissuance preparation phase is separate from the issuer's10800-second clock and is not an extension of that clock. Root must accept and register this order explicitly.
2. `prepare` checks exact job source/workflow commit, actual run/attempt decimal IDs, canonical absolute workspace/temp paths, fresh deterministic names, selected provenance, original rows/maps/callbacks and metadata. It exclusively creates private bootstrap/tool-state paths outside checkout. It observes only `/usr/bin/docker` bytes/metadata and `/run/docker.sock` metadata, and rechecks those observations before returning. CLI must be root-owned, regular, single-link, mode0755 and match Root's literal byte pin. The socket must be a root-owned socket with an exact six-integer identity. No Docker execution or socket connection occurs.
3. The constructor returns `(absolute_path, actual_file_sha256)` references for grant and runtime. Pass those exact references to the already-reviewed `issuer.issue(environment, issuer_sha256, execution_grant, runtime_contract)` **once**. It issues the12-field clock and publishes the existing six environment bindings. This resolves the issuer's requirement that references exist before clock issuance. The constructor has no clock issuer, clock schema, renewal API or new grant field.
4. Perform authenticated checkout under that retained endpoint. Call `verify_checkout(..., deadline=retained_endpoint)` only through the trusted issuer/controller bridge. The endpoint must come from the existing authenticated clock/domain validation and controller J selection; the constructor's numeric parameter alone is not clock-domain or issuer attestation. The verifier reads only exact selected paths, checks their pins/modes and retained private contract custody, rechecks tool-state emptiness/runtime identity and output/cache absence, and returns the12 pins. It neither scans a tree to select sources nor executes project code. Root's existing full packet scanner remains responsible for complete source-closure checks, and actual callback/code/frame admission remains with the controller/Session.
5. Invoke the existing composed controller with the same external references/clock and Root-selected packet/pins. Retain the precreated files/descriptors until controller custody transfer; `Owned.close()` then releases descriptors while leaving the files for the designated owner. On a preparation failure, `Owned.dispose()` attempts only retained owned files and directories in reverse order. A future trusted workflow owner must define final retirement of the bootstrap files and empty tool-state directories; there is no automatic broad directory deletion or workflow publication in this proposal.

The model suite executes the exact9e327 issuer body once against the constructor's real private reference files using a mocked clock domain/time. It then checks the selected258 copied source paths under the same endpoint and confirms unchanged clock bytes. This proves the modeled reference/phase composition only. It is not actual trusted workflow issuance, grant admission, or a real clock-domain validation.

## Paths, schemas and disposal

For run R and attempt A, deterministic paths below `RUNNER_TEMP` are `development-bootstrap-R-A`, `development-toolstate-R-A`, `development-output-R-A`, and `development-cache-R-A`. The constructor creates only bootstrap and tool-state trees. Their parents are distinct from checkout. Bootstrap JSON files have mode0600 and one link; the bootstrap/tool directories have mode0700 and effective-user ownership. Tool HOME/config/tmp are distinct, empty mode0700 directories; grant/runtime/selection files are never placed in them. Actual transport will retain its existing checks.

Grant preserves exactly17 schema2 fields, added_seconds1200 and existing development-only behavior. Runtime preserves exactly `{cli_sha256, endpoint_identity, env}` and its seven fixed/selected environment keys. The grant's actor hash is the canonical runtime byte hash. The recipe commit comes from the immutable integration lock, not the actual source commit. Initial argv and hash use the existing19-item integration argv, adapter output `D/repository-handoff`, one view `D/repository-handoff/original-view`, absolute view metadata paths and existing12 pin selection. Original view remains160 files (original159 plus its lock). The constructor creates no view, producer, image, credentials or actor alias. Status22/live12 behavior and the original freeze4/input71 custody remain selected by the unchanged initial source/metadata; no test substitutes a new original scanner or acceptance gate.

No-follow ancestor traversal, stable opened/named file metadata, exclusive creation and retained inode descriptors support source-role custody. Disposal refuses replaced/foreign nodes, dangling symlink substitutes or unexpected directory contents and reports cleanup failure; it preserves the exact first exception. The controls include a partial write interruption, late deadline after partial bytes, new-directory open failure, foreign substitution and first-cause conservation. These checks do not establish security against hostile same-UID writers or universal syscall fault/race coverage. Private modes and nonce do not authenticate a trusted workflow by themselves.

## Remaining integration and measurement limits

Root must supply final external selection/peer/CLI pins, exact delivery custody for precheckout bytes, constructor and clock body registration, workflow launcher/CLI wiring, authenticated clock/domain/J bridge, scheduler-start interpretation, and final bootstrap retirement. None is granted by this local receipt. The source verifier authenticates selected rows; whole-current-root source admission is the existing controller packet scanner's separate responsibility. Runtime observation does not establish daemon readiness, native actor success, source/Git publication or hardware acceptance.

The60-second preparation ceiling and issued+10800 owning-step envelope do not prove equality to GitHub's scheduler180-minute job end. Preparation precedes issuance, the scheduler may terminate earlier, and no scheduler-start monotonic mapping was measured. Deadline checks around finite reads/writes and best-effort cleanup are cooperative source bounds, not hard-real-time guarantees or measured aggregate CPU/RSS/raw-I/O accounting. The suite uses only private Python file/stdjson models; it performs no actual Docker runtime observation and no native/public actor. All model work uses the owned project TMPDIR and `python3 -I -B -S`; no PYC was produced.
