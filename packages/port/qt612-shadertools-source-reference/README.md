# Qt6.12 Shader Tools source reference

This original aarch64 development recipe prepares the matching `qsb` and ShaderTools provider needed by the full Qt6.12 Declarative/Quick candidate. It is source-audited and unselected. No library, tool, shader or consumer was compiled or executed. No package installation, signing, native/M2 acceptance, Root resource grant or frozen349 target compatibility is claimed.

The official component archive is 1,244,684 bytes, SHA256 `c7d84f436e1aaef39fdcadebf2bd71bdf24dc69497e13f2e0198873cbbfea2ab`, with 330 files and 10,266,940 uncompressed bytes. Its primary checksum and mirrorlist agree. Only this bounded component was downloaded and retained for offline source controls; no monolithic Qt bundle was acquired. Release tag `v6.12.0` peels from object `a386823038d8ea1c52e2414f4e82b6e59fd4e3fc` to commit `bccd516b990a6396900051470ac86cc27a7042ea`; primary commit metadata gives tree `00cf97838baca2f2b1a4833f6498ca39e6e073ec`. ShaderTools' tracked `.tag` uses `$Format:%H$`, so the archive records the **commit**, unlike Declarative's `%T` template. The exact upstream prerelease marker is retained, never rewritten. Archive signature authentication remains unperformed.

The recipe requires `cachy-asahi-qt612-gui-server-source-reference=6.12.0` normally installed, with its matching Core/Gui private and public ABI and BuildInternals. CMake exact-version/provider-path checks refuse the host's Qt6.11.2 and prevent the upstream successful-but-empty Gui-missing branch. Configuration must generate the qsb and shared-library Ninja rules and all three exported CMake packages; an absent qsb cannot masquerade as successful configuration. No dependency/version/signature bypass is used.

Upstream unconditionally builds its bundled glslang and SPIRV-Cross libraries. The exact 168 vendor files (9,682,834 bytes) are pinned, with complete membership and byte checks before compilation. Actual Qt attribution records identify glslang16.3.0 and SPIRV-Cross `1a6169566c73d3da552748fc372fe2bbb856e46e`. The glslang bundle includes BSD3, MIT-Khronos-old, Apache2, GPL3 with Bison exception2.2 and AML-glslang terms; SPIRV-Cross records Apache2/MIT-Khronos-old. All 19 original root licenses, vendor license/copyright and attribution files are retained and copied into the package. The qsb source specifically uses GPL3 with the Qt GPL exception; the library retains its LGPL/GPL alternatives. `LICENSE.third-party` summarizes, and does not replace, these original notices.

The stage checker requires the AArch64 qsb executable at `/usr/lib/qt6/bin/qsb`, its normal loader and shared ShaderTools dependency, exact library SONAME, public/private/Tools CMake packages and imported qsb target, pkg-config, global/private/RHI headers and the shader macro under **Qt6ShaderToolsTools**. It inspects all ELF bytes using the exact maintained project parser, reports GNU symbol-version metadata and DT_NEEDED, and refuses unknown dependency/ownership paths, system glslang substitution, escaping aliases and missing notices. Static 16KiB ELF geometry is not native or hardware proof. QShaderBaker and QSpirvCompiler are explicitly version-sensitive RHI/private APIs, not an invented stable public ABI.

Future `check()` first builds a normal `qt6_add_shaders` consumer against only its own ShaderTools/qsb build and the selected base. Fixed vertex (standard+batchable) and fragment inputs generate SPIR-V100, GLSL100es/120/150, HLSL50 and MSL12 through the normal `--qt6`/CMake defaults. Thirteen bounded qsb CLI calls cover version, both bakes, reflection and SPIR-V/GLSL/HLSL/MSL extraction; known inputs, outputs, uniform offsets/matrix stride and sampler bindings are checked independently from the fixed GLSL sources and exact Qt reflection writer. The API consumer also exercises QShaderBaker, private QSpirvCompiler, shader serialization and CMake-generated shader resources. Each CLI call has a 10-second timeout and the API invocation 60 seconds; the sum is 190 seconds, separate from source/consumer compilation under a future whole build deadline. No optimization, fxc/dxc, Metal native compiler or spirv-opt subprocess is selected. Shader source generation/reflection would not prove GPU execution or M2 support.

`prepare()` verifies source tree identity, notices and exact bundled inputs. `build()` runs serially with normal dependencies and target checks. `package()` installs only into DESTDIR and applies the payload/notice contract. The recipe adds no install script, ALPM hook, service, automatic replaces, host package mutation, or network inside build functions. `lifecycle.DATA.json` specifies the maintained disposable runner's later normal signed install/remove/reinstall checks, retaining the base and private-state guards.
