# GUI18 native evidence adapter v1

This separate family binds the exact GUI recipe at
`b05267833d497ef034576741bf31968019a526c3`. It supplies passive package/native
receipt, dependency, smoke and lifecycle component validators. It does not
dispatch, grant authority or authenticate an actor from JSON. `native_entry()`
always refuses. C's separately frozen GUI producer and genuine native outputs
remain required. The bootstrap/040840 adapter, recipes, actors, workflows and
shared manifests are unchanged.

The accounting is thirteen bootstrap Qt modules plus five GUI additions:
EglFSDeviceIntegration, EglFsKmsGbmSupport, EglFsKmsSupport, WaylandClient and
WlShellIntegration. The other54 components remain outside scope. No72-module
catalog, original official0bd04f correspondence or retroactive Source79/final779
acceptance is claimed. Native execution, installation, capacity, M2 and release
acceptance remain unbound.

## Bound source and original package

`common.inspect_recipe(checkout_root)` verifies b052's complete36-file namespace,
whole map, modes and all source bytes, including the exact fourteen active recipe
files. The archive, four security patches,173 notice files and serial scheduling
policy retain the recipe's original pins. A passive CLI is available:

```sh
python3 -I -B scripts/port/qt612-gui-native-v1/entry.py --recipe-root /absolute/b052-checkout
```

`archive.inspect_archive(path, work, recipe_root)` reads the original single-XZ
package, with512MiB compressed,2GiB expanded,128MiB/member and100000-header bounds.
It checks safe USTAR/PAX names, owners, modes, aliases and complete original
PKGINFO/BUILDINFO/MTREE operands. Metadata must match the exact GUI package,
version,39 runtime dependencies,19 provides,2 conflicts and original PKGBUILD
SHA. Hooks, install scripts, backup entries and replacements refuse. BUILDINFO
and build dates are not rewritten. MTREE is retained by whole pin; its semantic
validation remains with the normal package checker.

Temporary private materialization invokes only the whole-pinned b052 stage
checker. It requires the selected18 shared providers,12 fixed plugins,5 tools,
exact173-notice policy and complete payload/alias/hash/mode metadata. Every ELF
must be AArch64 with structural16K load geometry. Needed libraries, interpreter,
GNU version definitions/requirements and unavailable external providers are byte
observations, not successful loader or hardware checks. Temporary payloads are
retired after inspection; no extracted member executes.

## Original native-pair provenance

`native.validate_pair(...)` consumes two distinct retained ordinary attempt roots,
the original comparison and an independently selected producer binding. Its
docstring gives the closed binding schema. The actual C producer binding pin,
entry body, image, sorted inventory, nonce and clean environment IDs are external
operands; no C commit or execution fact is invented.

Every original provenance-file operand, all fifteen source/recipe snapshots,
entry body, package archive, validation/environment/configuration/notices/stage
receipts and complete build/check logs must reopen under their whole pins. Both
real-check markers and normal successful native record fields are required.
Archive, payload, PKGINFO and BUILDINFO equality remain strict. The current
archives/stages/normal validation reports must agree; plan labels or a machine
declaration alone are insufficient. The result still says
`native_execution_authenticated:false`: actual supervisor custody and native
acceptance are Root/C decisions, not conclusions from a self-authored receipt.

## Signatures, installed providers and smoke contracts

`trust.verify(...)` retains the unchanged public-v4 TEST verifier algorithm via
two exact reversible substitutions: the GUI scope and its pinned parser path.
It requires current external trust, full fingerprints disjoint from every
official primary/subkey, exact original tuple pins and an explicit caller-owned
supervised callback. Original, deterministic one-bit tamper and empty-keyring
unknown-key controls must all retain natural exits/reaping and bounded original
status output. There is no default subprocess, signing, import or network actor.
The caller must authenticate the complete official-key exclusion set and current
public-trust selection through independent custody. MODEL tests do no crypto.

`runtime.validate_dependencies(...)` requires original stage/snapshot/inventory/
provider tuple bytes, all retained raw ELF bodies and package database file
metadata. Every installed package has exact version/architecture/provides and
original archive/signature/provenance/database pins. All used GUI files and
aliases must match actual package ownership, modes and hashes. Each DT_NEEDED
edge follows the supplied actual loader lookup to an unambiguous owned provider;
the transitive closure and normal AArch64 interpreter are checked. Each retained
ELF in that closure, including external libraries and the interpreter, must have
power-of-two load alignment of at least 16 KiB and congruent file and virtual
addresses at that alignment. Every needed GNU version must have a matching
visible definition/hash. RPATH, RUNPATH, loader
audit/filter overrides and uncontrolled loader environment refuse.

The39 normal dependency expressions are passed unchanged to the original
supervised `pacman -T` evidence. This adapter does not replace ALPM's version or
provides solver. Complete signed-input/current-key/ALPM authentication still
requires C's trusted original execution; an archive/signature pin is not signature
mathematics. The GUI signature component alone cannot authenticate every
baseline package.

`runtime.validate_smoke(...)` rederives the dependency component from original
inputs before joining bounded owned-supervisor receipts for all18
`RTLD_NOW|RTLD_LOCAL` loads, the original b052 offscreen GUI marker, and normal
Qt CMake discovery with correct public/private module target names. Output,
observations, child identity, start/natural-exit/reap/pidfd-retirement events,
code pin, image and nonce must join. These are concrete receipt contracts; the
separately granted C integration must implement the named probe callbacks and
retain real outputs. This family supplies no probe actor or successful runtime.

## Replacement, rollback and removal

`lifecycle.reviewed_plan(...)` makes a finite DATA plan for atomic13→18 conflict
replacement, GUI reinstall, reverse18→13 replacement, upgrade again and ordinary
GUI removal. Both original signed package tuples must be selected externally.
An explicit separate TEST configuration must actually contain only
`Required TrustedOnly` signature rules, aarch64 and its selected public GPGDir.
No unsigned, dependency bypass, pre-remove, recursive removal, no-save or
sync/upgrade fallback is permitted. Interactive ALPM conflict/proceed receipts
must name only the exact expected package pair; no global conflict permission is
generated.

Every stage retains exact inventory and all-installed-dependency checks. Removal
must naturally refuse when retained consumers need Qt; successful removal is
valid only when normal dependency checks permit it. Missing-dependency and
foreign-owned overlap negatives run only in separately selected sibling
executions and must preserve the appropriate state.

Complete before/after user and other-package configuration snapshots compare
contents, modes, uid/gid, aliases and owners, including `.pacsave`/`.pacnew`.
User-owned files are never relabelled as package payload. Main/sibling commands
bind the independently selected image, supervisor and distinct execution IDs.
This family does not collect or modify the real user's configuration.

## Composition and remaining execution boundary

`adapter.review_components(...)` joins all components using the externally pinned
closed request in `UNBOUND.DATA.json`. The unbound template cannot pass. The
signed archive must equal both original native archives; the retained stage must
equal current archive bytes; installed package pins must join signature/native
receipts; lifecycle payload/dependencies and its actual configuration must match
the original package. Runtime and lifecycle must use the same selected
image/supervisor. Inputs are reopened after the explicit signature callback.

Even complete DATA joins return no Root grant/native/capacity/hardware/release
acceptance. A received SHA or an `issuer` string cannot authenticate custody.
Root must select C's frozen GUI producer, resource/runtime/role bindings and
genuine outputs before operational integration. No shared manifest change is
made; the proposed integration is this explicit component boundary.

Run each `test_*.py` separately with `-I -B -Werror` and an explicit private
`TMPDIR` when shared `/tmp` is occupied. Fences precede implementation imports.
Tests use labelled MODEL archive/receipt/crypto boundaries; the genuine b052
source namespace is checked separately. There are no real native package,
signature, image, kernel, lifecycle, M2 or performance results in this family.
