# Private repository handoff — held implementation

This adds a separately authenticated execution chain around the frozen original
producer. It is not registered for native use. Original159 source, recipes,
eleven repository cases, public exporter and old79-case gate remain unchanged.
Tests use modeled native/transport/authority fixtures plus real temporary files,
pipes and signals. No Docker, GPG, installation or native admission has run here.

`entry.py` requires Python `-I -B -S`. Its CLI only authenticates the externally
pinned exact seven-file runtime map (`entry`, `capture`, `producer`, `launch`,
`transport`, `supervisor`, `broker`) and reports source preflight. Runtime/testing maps proposed under
implementation review artifacts are observations, not adopted registrations.
Root must authenticate the launcher's own bytes/mode before starting Python.
Source APIs require the existing absolute source cutoff; `original_modules`
also requires a distinct existing job/operation `verification_deadline` for its
postexecution reread. Neither cutoff is renewed inside the loader.

The loader captures bytes/modes before compile, excludes PYC, resolves captured
project imports explicitly and checks standard-library origins. `original_modules`
authenticates the unchanged159-source lock and executes its bounded known host
module graph with real source paths; it restores module slots/import paths.
`dependency_entry` requires separate external launcher/map pins for the existing
collector and phase successor and restores their module slots. There is no
old-schema post-terminal downgrade. The narrow provenance URL source delta needs
root's new collector-map and phase dependency rebind before these loaders pass.

## Checkpoint and ownership boundaries

Before the exact original A-revocation command, the producer sends actual A7+B7
positive command records/stdout, public certificates and signed-object hashes.
After original public export it sends the B alias map/signature/receipt, before
cleanup. Original command order and cleanup remain mandatory. Hash custody is
not full package-byte custody; later exact exports must match these hashes.

There are exactly two RC NH1 frames: canonical ASCII JSON with schema1, purpose,
nonce, sequence, phase, base64 payload/hash and prior frame digest. Frame SHA
covers canonical JSON without marker/newline. Each decoded payload is at most
4MiB, wire at most6MiB, handshake at most30 seconds clipped to caller deadline.
The host fsyncs file and directory and rereads identities/hash before issuing
the exact nonce/sequence/phase/frame digest ACK. There is no key, home, trustdb,
agent or standalone revocation-certificate copy. Reserved/malformed/partial
protocol bytes fail closed and never reach the unchanged public log/exporter.

The new create boundary registers64-hex CID before start, checks exact immutable
image/name/nonce/mounts/root-six-cap/resource/stdio policy and terminal state,
removes only that proven CID, and verifies both name/ID absent with full daemon
IDs. Partial creation is never PASS; recovery requires CID-file and full inspect
agreement. Native exit zero is required independently of two successful ACKs.
Late cancellation invalidates the private authoritative launcher receipt even
when cleanup has completed. A forced namespace removal cannot certify the
original producer's Python cleanup ran.

## Dependency graph loader correction — 2026-10-12

Actual fresh collector and phase source loads reproduced a deterministic failure
in the prior seven-source runtime: executing the legacy launcher under a
stdlib-only importer made its nested provenance import of `common` fail. The
new `dependency_entry` authenticates and compiles a private captured graph
directly. It requires the canonical collector/phase launcher and source-map
paths, an external launcher hash, the external map hash and the existing finite
absolute deadline. No actor starts from this API.

Collector loading authenticates all seven collector files and the four frozen
predecessor files. Phase loading authenticates its five files, that same complete
collector seven and all four predecessors before any project compilation. The
