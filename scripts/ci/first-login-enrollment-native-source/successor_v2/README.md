## What this implements

`prepare.py` checks the externally reviewed whole profile, all42 recipe leaves,
local SHA256 checks, complete metadata and each maintained helper before output.
It reuses the pinned v1 nofollow/single-link reader, Git tree calculation and
atomic no-replace publisher. It emits59 files with a closed58-member source lock:
the current recipes, generic builder/entry/comparison/static inspector, exact
held ALPM/tools helper bodies, constructor basis, current adapter, prospective
inputs and three reviewed-input digest sets. It runs no recipe/build/package,
GPG, Docker, Reader, lease, resource query or download. It emits source DATA,
never an actual source/ref/run binding or a native-ready claim.

```bash
python3 -I -B scripts/ci/first-login-enrollment-native-source/successor_v2/prepare.py \
  --root /ABSOLUTE/REPOSITORY \
  --profile-sha256 8ad3641649e395b1202363e3368f713f65252a743b12e3a8d69430e4f82bc171 \
  --output /PRIVATE/OWNED/FRESH-SOURCE
```

`native.build_vectors` selects six normal dependency-aware/check-enabled builds
and three complete-byte comparisons using the maintained offline generic builder.
`build_pairs` calls only the original owner's bounded command callback, verifies
actual check logs and requires complete archive/content/PKGINFO/BUILDINFO pair
equality. The compressed-byte equality also binds MTREE. It propagates first
failure. CLI03 requires14+6 checks, UI02 requires38+6; the Enrollment04 gate joins
the exact full relocated/namespace/refresh/transition/revocation report. Old
versions, partial/stale logs, skipped checks, tamper and failed comparisons hold.
No `--nodeps`, `--nocheck`, dependency download or privileged fallback is added.

`native.lifecycle` is an internal adapter for the existing owned signed-image
callback. It requires exact Setup8 and current three archive/signature pins,
strict fresh TEST signer status, source-bound16/6/8 payload maps, and one closed
local-only required-signature configuration/private log. It verifies complete
ALPM inventories, installed body/mode/owner, two install/remove cycles, ordinary
user help smoke and final payload absence. It removes candidates before Setup8,
then invokes the original owner's required protected-state restoration check.
Failures propagate to that owner's normal cleanup. Read-only help is not a GUI,
interactive user journey, changed-version upgrade, or complete target transaction.
The adapter is not a standalone actor, supervisor, trust issuer or Reader.
