# Private backend producer-to-consumer handoff

The existing public workflow retains its seven control receipts. Source207 has no private pair hook. This proposal adds an explicitly selected private route that uses the existing backend, Context4 adoption and staged product APIs.

Run `python3.14 -I -B emit_backend_pair_hook.py --source "$EXACT_SOURCE207_TREE" --launcher "$EXACT_LAUNCHER" --output "$FRESH_PRIVATE_DIRECTORY"`. The emitter verifies both whole predecessor bodies and emits only the two reviewed proposals.

A selected trusted runner passes `--private-backend-pairs` to its reviewed launcher. The flag reaches the same finite controller through its existing argument vector. ## After launcher and material close

Run `python3.14 -I -B backend_successor_adapter.py --mode private-same-job --selection "$SELECTION" --selection-sha256 "$SELECTION_SHA256"` with the outer selection fields `schema: 1`, `kind: ROOT_SELECTED_PRIVATE_SOURCE207_HANDOFF_V1`, `issuer: Root`, `approved: true`, `snapshot`, `source_root` and `request_pin`. The `snapshot` is the exact existing [private snapshot selection](SOURCE207-BACKEND-HANDOFF.md). Select the request whole pin independently. The default opens no private files.

The output is `producer-handoff` under the chosen runner-private root. It contains the exact prior snapshot, two original pair proofs, 13 direct bodies and a whole-pinned `producer.json`. The handoff validates both copies of each actual native package inside the capsule against the original pair proof. It carries no raw launcher request, raw owner or daemon log, authorization material, secret environment, or output-directory traversal.

## After the hosted original is terminal

The Reader expects 22 support roles. `consumer` returns the names of any missing independent inputs. Their authentic bytes and pins come from the independent review boundary.

| Review | Required roles and facts |
| --- | --- |
| Runtime and domain | `runtime`, `domain_qualification`. Actual image, scope, command and container retirements, kernel resources and private trust absence. |
| Image and commands | `image_qualification`, `command_observations`. Independently selected whole material and primary fingerprint observations, bounded actual command results and their original-receipt joins. |
| Prerequisite and material | `prerequisite_qualification`, `material_qualification`. Actual wall/monotonic events, physical scope activation/outcomes and independent supervision joins. The current public receipts alone do not supply every clock, resource and retirement observation. |
| Successful provider and components | `completion`, `component_enrollment`, `component_first-login`. Successful original job authority and separately reviewed exact pair/package decisions. |

Supply the original frozen Source file map, whole-pinned Reader selector, producer pin, authentic independent refs, and trusted observation time. The unchanged full Reader must pass before `stage_product` can write inputs for a later exact UI or lifecycle selection. Its output uses the existing `ROOT_SELECTED_PRODUCT_INPUT_REFS_V4` contract and passes the committed assembler’s preflight over both archives, both actual TEST signatures, original completion/delegation/context/pair, and separate Root component and TEST decisions. The first-login package is the UI input. Enrollment and first-login are lifecycle inputs alongside the later UI product.

Actual successor source closure, persistent private custody, authenticated runtime observations, completed original job, genuine TEST signatures, next selection and same-source native consumer remain pending. The consumer still uses Context4 against its own poststart hosted context and performs fresh TEST verification. Product staging does not establish an account login or runtime UI PASS.
