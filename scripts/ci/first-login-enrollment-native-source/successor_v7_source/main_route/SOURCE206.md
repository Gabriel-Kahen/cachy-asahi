# Source206 backend

Use the existing workflow 420175404 and the standard `backend` stage with
`products={}` and `retention=null`. Native248 command 2 is a checkpoint
within the backend. The registered workflow checks out the exact `hosted_current_v3.py`
launcher from the Root-selected Main commit. The outer caller and terminal
reader independently select `reader_current_v3_source206.py` from that Main
commit. Its 284,823-byte body is the exact C908 projection of the original
Reader, which remains the Source205 member.

Prepare the [backend selector](BACKEND-CHECKPOINT.md) with
`kind=SOURCE206_BACKEND_DATA_SELECTION_V1`, Source
`12827a098e9401998496405efde9de751367a14b` at
`refs/heads/codex/current-onboarding-staging-v7-20261118-r2`, its retained
Root publication receipt, its exact 21,451-byte profile and the selected
Main Reader body. Set Main to the accepted commit and tree containing the
Reader, and independently check all eight whole input pins. The normal
checkpoint command emits the unissued case and the exact C908 certificate
descriptor. The case reserves a separately issued live TEST trust record.

Root supplies the seven bound operands with their existing scope checks.
For `test_trust`, use the exact displayed `public_key` descriptor and
fingerprint. The `Root_admission` value carries canonical inline `json` and
its whole `pin`. The JSON uses `issuer=Root`, `approved=true`, scope
`CURRENT_ONBOARDING_IMAGE_INPUT_TRUST_ONLY`, the same fingerprint,
`issued_epoch`, `expires_epoch` and `public_key` as a whole file reference
with the selected GitHub runner workspace joined to the Source member.
The real assembler compares that absolute path to its resolved certificate.
The approval must cover the whole issued case. The case and approval both
expire by epoch `1795474060` (2026-11-23 22:47:40 UTC), inside the certificate's
lifetime. Root independently supplies the official trust record, live
registration, 21 redirect decisions, exclusive reservation and custody.

For a passive qualification invocation, select canonical JSON with
`schema=1`, `kind=SOURCE206_BACKEND_QUALIFICATION_SELECTION_V1` and `files`.
Its roles are `checkpoint`, `core`, `profile` and the seven Root operands
`case`, `admission`, `runtime`, `registration`, `readback`, `once`, and `request`.
Each file has an absolute `path`, `bytes` and `sha256`. Select the exact
file pins and current observation time independently.

```sh
python3 -I -B checkpoint.py --selection /absolute/qualification.json \
  --selection-sha256 SHA256 --now ROOT_OBSERVED_EPOCH
```

Qualification emits the unchanged dispatch-body data for the existing Root
operator. An expired case or approval refuses live qualification. The replay
command in the [backend checkpoint guide](BACKEND-CHECKPOINT.md) takes
`kind=SOURCE206_BACKEND_TERMINAL_SELECTION_V1`, the exact Source206 profile,
and the versioned Main Reader. Replay uses the historical issue and observed
epochs and matches the public TEST certificate path to the retained runner
context. A retained checkpoint does not itself qualify backend products.
