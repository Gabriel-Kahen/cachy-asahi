# Delegated current Source constructor v4

This separate DATA constructor preserves v3 and Source139. It imports only the
finite whole-pinned v3 construction closure and uses its strict original basis,
carrier, recipe, trust-proof and inventory checks. It executes no owner, route,
executor, Reader, package, GPG, network or lease operation. No new actual Source
has been assembled or published by the focused model tests.

`assemble(repo, closure_raw, carrier_raw, manifest_raw)` requires one full actual
Git commit for the complete declared new pipeline closure. Missing commits,
uncommitted body pins, absent callbacks, role collisions or missing files refuse.
`closure_template()` returns the default unissued schema: commit/files, every role and
executor/Reader entrypoint are NULL; all `actual` selectors are NULL. Tests use
explicit inert code in tiny local Git repositories, never historical/private
fixtures or API-shaped claims of real operational qualification.

The closure kind is `COMMITTED_DELEGATED_CURRENT_PIPELINE_CLOSURE_V4`, schema4,
operation `first-login-enrollment-ui-current-v2`. The default `roles` has exactly:
`v3_basis_owner`, `v3_basis_route`, `context`, `image`, `image_executor`,
`delegated_owner`, `route`, `retention`, `public_reader`, `policy`, `workflow`,
`encoder`, `owned_process`, `hosted_launcher`, `inputs_assembler`.
`closure_template(with_host_prerequisites=True)` adds exactly `host_prerequisites`,
`host_prerequisite_plan`, `host_prerequisite_tools` and
`host_prerequisite_runner_basis`, also initialized NULL. Only the complete15- or
19-role roster is accepted; partial or unknown additional roles refuse. The
optional four descriptors also appear under the same canonical names in
`delegation_programs`. Their presence describes available code and grants no
`allow_host_prerequisites` capability.
Each value names a distinct committed Source-relative member in
`files`; each file row contains exact `bytes`, `sha256`, `mode`. Up to96 complete
declared code/helper rows are allowed. `entrypoints` explicitly names the actual
committed `image_executor`, `public_reader`, `hosted_launcher` and
`inputs_assembler` functions; each is NULL until that actual committed function
is available. `actual` has exactly
source/ref/run/job/Root_delegation/Root_trust/Root_resources/Root_runtime/
actual_images/publication, all NULL. These fields create no Root authority.

The immutable `v3_basis_owner` and `v3_basis_route` are pinned old callback bodies
in the same commit, retained as the DATA basis so strict v3 assembly remains exact.
Neither is selected as the delegated execution owner or route. The committed new
owner explicitly reuses the same whole `v3_basis_owner` body only as its reviewed
`local_callbacks` helper for `SignedSession`; it never invokes its old Root
admission or independently qualified-image gates. The new owner must
declare API `CURRENT_ONBOARDING_DELEGATED_OWNER_V3` and export the real
`open_delegated_session` and `launch_delegated_lifecycle`; the new route exports
`run_registered`, with no fake `admission` wrapper required. Context, image,
retention and encoder expose their committed public functions. The workflow is a
separate committed `.github/workflows/*.yml` dispatch workflow; the policy is a
committed JSON body. Callback presence is a construction check, not evidence that
those operations have run or that a public Reader has qualified their results.

`project_materials(v3_material_map, files)` is the exact projection API. `files`
is the verified Source dictionary `{member: (raw_bytes, mode)}`. The result has
schema4, kind `DELEGATED_SOURCE_RELATIVE_MATERIALS_V4`, `aliases` (original role
to fixed lowercase role), and `materials` (alias to `{member,bytes,sha256}`).
The exact59-role roster is closed:23 official archive/signature pairs,
five Setup8 roles, three stage inventories, two official catalogs and the three
prospective/vector roles. Official aliases are `official_<package with hyphens
replaced by underscores>_<archive|signature>`; all remaining mappings are
explicit in `ALIASES`. Unknown/missing roles, alias/member collisions, unsafe paths or a pin
that differs from the actual body refuse. Only `path` becomes `member`, keeping
the same `carrier/` path and body. Original carrier/proof bytes are never edited.

The new schema4 `successor_v4_source/program.json` is the explicit delegated
registry. It selects the actual delegated owner/route and all whole role pins,
names their real callbacks and records the single closure commit. It labels the
old v3 registry DATA only. A new executor/workflow must explicitly select this
registry; invoking the old v3 dispatcher still invokes its old strict gates.
This constructor neither supplies dispatch wiring nor weakens those gates.
Its separate `delegation_programs` descriptor map records the canonical module

`owned_process`, `hosted_launcher`, `inputs_assembler` and `encoder` from the same
named roles. These are whole Source descriptors, not an issued delegation.
`retention_callback` is explicitly `retain_delegated_stage`.
