# Separate managed Welcome GUI generic16K diagnostic

This manual CI lane derives the accepted `welcome-managed-gui` runner without changing that lane, the generic16K smoke profile, product recipes, or the Asahi platform stack. It tests an installed 593-package private desktop filesystem in QEMU's generic ARM machine with software graphics, a real systemd user manager, and its real private user bus. It is not M2, Apple platform, accelerated graphics, physical input, performance, release admission, or hardware acceptance.

## Exact inputs and source audit

The kernel is Asahi source revision `94fb23346d522edf53722357c426a3e58030beea`, historical tag archive `asahi-7.1.13-3`, 262965559 bytes, SHA256 `874ef68d04ac8c831b90bb01a387cfabb58fceb60842c49a0d0e58bcd6c146ad`. The canonical `tools-generic16k/acquire_kernel.py` and `retained_kernel.py` supply the same archive-only cache, fixed retained source seed and bounded direct fallback used by the existing tools lanes. Every restore/seed/copy is hash verified; the builder verifies the same bytes again before extraction. The exact archive is saved before building, so cleanup does not discard reusable source. No new fetcher is added. Kernel sources retain their upstream GPL-2.0 license. Derived fixture helpers retain MIT notices and the existing source/build contracts. No new upstream userspace, Rust stack, bootloader, package versions, or dependency replacements are introduced.

`kernel.fragment` adds the generic PCI virtio GPU, root disk and event-port drivers plus the namespaces, cgroups, local sockets, PTY, eventfd, seccomp and filesystem APIs required by the existing systemd/desktop fixture. All drivers are built in (`CONFIG_MODULES=n`). Expected release is `7.1.13-generic16k-managed-gui`. The derived helper changes only `main`, `usage` and `run`: the separate profile/exact release and a compiler-output scan correction. The scanner tolerates ENOENT only below its private compiler-output directory while the child is active; source/root/permission errors and final scans remain strict. Quotas, log bounds, deadlines and cleanup remain unchanged. The same correction addresses the observed `.bitrev.o.d` race in tools run38924169611; it has not been runtime tested here. Configuration is checked against all 89 explicit fragment values plus the original two diagnostic values. This source audit does not prove that Kconfig retains every requested value: the actual configure step must pass that check.

Before implementation, all 590 exact upstream package archives (574 base plus 16 additions) were size/hash verified and inspected. Their 4,027 native ET_EXEC/ET_DYN inputs were little-endian AArch64 and had PT_LOAD alignment and virtual/file-offset congruence compatible with 16K pages. Known Guile EM_NONE `.go` containers and firmware/kernel/debug data were classified separately. The four retained Welcome/Doctor archives, their two identical pairs, all 23 recipe sources and all 13 installed payload paths are independently checked by the unchanged candidate verifier. The desktop settings payload contains configuration, scripts and data rather than native ELF. This audit is structural inspection of inputs, not successful execution.

## Runtime contract

Preparation only reads verified sources, verifies retained candidates and writes a new runner. The actual native build uses the already accepted kernel commands and tools on a disposable ARM CI runner. Installation occurs only inside that runner's owned Docker image and copied private disk filesystem. Existing Welcome and Doctor packages are installed using pacman; the existing GBM and accessibility fixture helpers are compiled into `/usr/local/bin` with explicit 16K linker alignment. Their sources and dependencies are unchanged. These helper copies are not claimed to be pacman-installed packages.

Before disk creation, a required read-only scan checks every native userspace ELF in the complete staged tree, including those generated helpers. This catches incompatible generated files or rootfs leftovers that an archive audit alone cannot cover. The Image/config/build receipt must match the exact source, helper, fragment, granule and owned build paths. The actual guest must report AArch64, 16384-byte pages and the exact release, joined by SHA256 to the same kernel profile used for its Image.

All existing gates remain: two managed phases, seven ordered QMP captures each, eight GTK/AT-SPI actions each, installed guide text and notebook selection, Doctor worker and CLI report, real user-bus/process identity, config preservation, normal owned GUI exits, existing log caps, original runtime cleanup and original owned574 producer retirement. Public retention replays the **generated 16K** event contract after verifying its generated-file hashes. Success additionally requires natural controller exit, controller process-group absence, producer image/probe absence, and removal of the completed private kernel work and copied Image. Failed or interrupted build work may remain for disposable-runner teardown; this lane does not claim active compiler-cancellation proof.

Fourteen exact frames remain mandatory and must receive coordinator pixel review. Files location remains qualified by visual review, the launched Terminal's exit status remains `UNOBSERVED_NONCHILD`, and the retained input's historical failed lifecycle receipt remains a failure. The separate corrected producer lifecycle run is not substituted into its immutable transport index.
