# GNU771 candidate-extraction source factory

This source-only factory reproduces all771 files of public
`4b2f8502655d2f4b65a20691247d1a54052089f3` from an explicit ordinary export of
public766 `cc04fe3a57bac24a516004dfb670a172e76ac517`. It holds757 leaves, changes
nine and adds five. All667 raw runtime leaves, fixed-case helpers and original
REMOVE helper/profile remain byte-identical. Normal remains the default
operation and both remains the default case in the exact emitted source.

```sh
python3 -I -B -Werror prepare.py \
  --parent /absolute/ordinary/cc04-public766-export \
  --output /absolute/fresh/candidate-source --known-context
```

Omit `--known-context` for the default NULL context. Both contexts emit the exact
same771 namespace and modes0644; only receipt `known_parent_context` changes.
`parent_source` and `expected_source` are fixed public input/target identities,
not caller-provided authority. `current_source`, `current_ref`, `current_run`
and `Root_acceptance` remain NULL in both contexts. The factory cannot bind a
run, issue acceptance or dispatch anything. Cancelled run40394251195 is not an
input and supplies no evidence here.

The complete profile is hard-pinned in `prepare.py`. It joins full before/after,
held/delta and payload maps. `payload/` contains four readable exact public
source files plus JSON DATA operands for the published extraction profile.
Counted text edits transform existing routes/template/tests, construct the exact
profile and deploy footer, then regenerate manifest/workflow seals. The complete
target map must match before staging. `inverse()` reconstructs all766 original
bytes through counted inverse edits and deterministic old-seal regeneration.

Generation never imports, executes, evaluates or compiles supplied source.
Public runtime-profile hashes are pinned DATA reproduced from the published
profile; they are not recomputed by executing source during generation. Separate
source tests deliberately execute the verified emitted source with actors
blocked, after full reproduction has succeeded. No whole historical source tree,
compressed executable, package archive, private configuration or key is bundled.

Inputs, factory and output must be mutually disjoint canonical absolute paths
without aliases. The output must be absent and its ordinary parent must already
exist. Supply ordinary Git exports without administration files. Stable-FD and
whole-directory identities, source/payload/profile/entry bytes are reread before
staging, including same-byte inode-replacement refusal. Every staged byte and
mode must match before the final local directory rename.

Run the focused suites with explicit pinned fixtures:

```sh
export GNU_EXTRACT_PARENT=/absolute/ordinary/cc04-public766-export
export GNU_EXTRACT_EXPECTED=/absolute/ordinary/4b2f-public771-export
python3 -I -B -Werror test_prepare.py
python3 -I -B -Werror test_source.py
```

Generation tests cover full equality/inversion, known/NULL CLIs, restrictive
umask, blocked execution/process/network APIs, wrong source/payload/profile,
aliases/overlaps/special nodes, late identity drift and pre-staging refusals.
Source tests cover the actual complete771 source entry and its766/older chain,
unchanged normal/REMOVE rendering, private667 extraction rendering/verification,
and the emitted real-child signal/fake-ALPM extraction and old REMOVE controls.
Those controls do not commit genuine libalpm or run a native package lifecycle.

The proposed read-only workflow checks out exact766/771 public revisions,
exports ordinary fixtures and runs both suites on Python3.12 and3.14. It has no
native dispatch, package acquisition, key, deployment or installation step.
Hosted execution remains separate from local validation.

Existing normal and REMOVE factories remain unchanged. This proposal can be
installed beside them as `scripts/ci/gnu-candidate-extraction-source/`, with its
companion workflow in `.github/workflows/gnu-candidate-extraction-source.yml`.
The frozen source/reader authors remain outside this adoption unit.

Genuine extraction/recovery, binary/source correspondence, native fit, paired
acceptance, M2, power loss, performance and release admission are not established
by source maintenance. Raw INSTALLDATE-only comparison and quarantine FD checks
retain the existing producer/reader evidence limitations. No new rollback or
automatic configuration-preservation success is asserted.
