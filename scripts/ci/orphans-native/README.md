# Orphan native candidate

Manual, unselected `cachy-asahi-orphans0.1.0-1` lane. Its eight source files
match the final orphan-assessment handoff. No product, existing native lane,
selected inventory, Apps/Cache owner or shared policy changes are included.
The submitted input policy and source manifest are **UNBOUND**. Root must
adopt the lane, verify the recorded final product bytes, fill the exact
product adoption commit in `candidate_source`, set policy status to
`ROOT_BOUND_FINAL_PRODUCT_SOURCE`, then run:

```sh
python3 -B scripts/ci/orphans-native/freeze.py --source "$PWD"
python3 -B -m unittest discover -s scripts/ci/orphans-native -p test_native.py
```

Freeze checks the original574 reference inventory, source closure and
already-present Python/pacman dependencies; it replaces the two workflow
checksum markers. Root owns publication and dispatch at the same exact
source/workflow SHA. Any frozen input drift fails before secrets. The lane
has its own concurrency group with automatic cancellation disabled. It
reuses the unchanged six retained inputs, fourteen public input files and
owned574 producer. No new dependency, waiver or fetch route is added.

Two separate read-only, offline native ARM clean containers use the accepted
Welcome builder and original standard `container-entry.sh`. `pacman -T`
and ordinary makepkg check dependencies. Both builds must run all18 original
real-libALPM recipe tests without skips. Generated SRCINFO, exact five-file
script/data payload, metadata, BUILDINFO and entire archive bytes must
match. An architecture declaration is not build evidence.

The trusted coordinator signs only the accepted archive using the existing
short-lived TEST signer, stops its agent, and mounts only that archive,
detached signature and public verification key into the lifecycle actor.
Private signing state is never mounted into that actor or either builder.
TEST trust is confined to the disposable verification keyring. Normal
signature- and dependency-checked ALPM operations perform exactly
574→575→repeat575→574→575→574. Only distribution hooks are masked and
scriptlets disabled in this disposable test; dependencies/signatures are
mandatory. All original574 non-directory payload nodes and package DB
records/directories, including ALPM_DB_VERSION, retain content/mode/owner,
device/inode/link count and modification/change times. The full-root reader
handles actual zero-byte metapackage files records and supplies its existing
4-million-node bound. Regular payload bounds are1GiB per file/6GiB total;
exceeding them fails rather than dropping packages. User home files,
symlinks and generated reports survive all package transitions.

At every installed checkpoint, two ordinary `alarm` user profiles invoke
the actual installed **default** CLI against `/var/lib/pacman`, without a
source checkout. Every observed DB node must be root-owned without group or
other write permission; the ordinary caller has no DB write/lock-creation
access. The real575 names/versions and574 base protection are checked and
full metadata snapshots must stay identical with no lock. Candidate lists
may be empty. This observes installed metadata; it does not prove payloads,
a release policy, removal authorization or hardware compatibility.

The same installed CLI separately assesses a physical temporary ALPM9
metadata fixture containing explicit/dependency reasons, versioned virtual
providers, optional dependencies with descriptions, a cycle and
base/platform/user protection. It explicitly plans two safe leaves, verifies
that plan and refuses needed/protected/explicit/unknown selections. That
fixture DB is also root-owned and nonwritable by the caller. A separate real
libalpm handle holds an empty transaction **only for the fixture counterpart**
to prove foreign-lock refusal and preservation; only that holder releases
its own lock through libalpm. The product has no transaction/removal APIs.
Hand-authored fixture metadata is never represented as installed payloads.
No actual orphan package is removed. Assessment and plans remain
`NOT_APPLIED`; apply, authenticated updater integration and accepted target
protection policy are unfinished.

Exactly four labeled consumers (probe, two builds, lifecycle) are persisted
before launch under an exclusive lease. Always-run cleanup checks actual
name/ID/image/label, retires only confirmed IDs, verifies their absence and
then retires the original producer. Active/unknown/foreign state preserves
the producer and fails. The closed192MiB artifact retains both archives,
build metadata/logs, source/license files, TEST signature/public key,
24 actual raw assessment/plan/observation reports, lifecycle/preservation
receipts and ordered cleanup. Private keys, user homes, caches, arbitrary
outputs and container layers are excluded. A failed or interrupted run
retains available diagnostics and cannot earn acceptance.

Host source/acceptance/ownership tests do not launch actors. Optional local
`test_fixture.py` requires an existing trusted libalpm16 and operates only
on disposable metadata; do not run it on the hosted Ubuntu coordinator or
install/waive dependencies for it. Native checks instead run in the actual
574 builder plus installed lifecycle. Source validation, native builds,
installed execution, 16K behavior, M2 Air workflows, physical recovery and
release admission are separate. No native/installed/hardware evidence is
claimed by this proposal.
