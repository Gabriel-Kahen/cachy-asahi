# F69 transport successor and separate GUI projection

This successor is based on `a767ec7577f9b4426b0391db822fc00704e31c2e`.
It adds executable passive adapters without changing that producer's original
files. `transport.lock.json` pins F transport commit
`75cee7ea27e1c9f3d10959e824b261764b9b1c3d` in `transport_basis/`, including its
independent verifier, 128 MiB/4096-file collector and pinned upload fragment.
The fragment is DATA outside `.github`; no workflow or upload is selected.

`transport_source.prepare_successor(source, source_map_sha256, license_root,
output)` accepts the exact a767 producer/helper pins and a separately pinned
predecessor Source. It creates a fresh complete Source map. Original helper
bodies and the predecessor map/input list are retained under `inverse/`.
The recipe view is F69's unchanged active14 plus `source.json`, an exact alias
of the frozen BUILD-CONTRACT. The Qt archive moves to `source-material/`.
The finisher projection changes only those snapshot identities; all current
archive, offscreen check, stage, package metadata and 173-notice gates remain.

The offline plan/catalog select the exact upstream URL, version and archive.
Five upstream grant/overview files are read from explicit `license_root` and
joined to F's pinned173 notice inventory. They do not establish legal acceptance
or represent all third-party grants. `prepare_cache` copies the whole pinned
archive into a fresh owned0700 cache with ordinary600 files. It downloads and
executes nothing. `verify_cache` checks its exact finite namespace and bytes.
`pair_commands` requires that external cache and appends the maintained
`--source-plan`, checksum, catalog and cache arguments. The actual Root-gated
normal builder independently runs `source_materials.prepare/stage`.

`transport_binding.export_pair` requires:

- A separately selected Source root and producer tuple: `source_commit`,
  `source_map_sha256`, `program_sha256`, `finisher_sha256`, `contract_sha256`.
  Program is `producer/transport_binding.py`; finisher is
  `producer/finish_pair.py`; producer contract is `transport-binding.DATA.json`.
  Executing adapter bytes and final compiled finisher bytes must match those
  pins. The Source commit and run tuple are external Root selections, not
  authenticated by JSON or inferred from hashes.
- The exact normal comparator receipt and a complete real pair. The genuine
  current-byte archive finisher must succeed before any PASS assertions are
  synthesized. Its file identities remain bound through collection/readback.
- Fresh disjoint staging, private retention and public output paths; an opaque
  store ID; and the exact F run metadata interface. No default run identities,
  uploads, process launcher, key access or authority document are supplied.

The public export contains exactly F's 14 payload roles and two transport
receipts. Provenance is unchanged. Stage is an unchanged alias; generated check,
license and pair receipts bind the actual qualified bytes. F's frozen collector
enforces the complete 128 MiB budget including receipts: exceeding it is HOLD.
It does not truncate or split a pair.

Every provenance `files`, `artifacts` and `recipe_inputs` operand is partitioned
exactly once into included bytes or an opaque exact-pin retention object.
Conflicting aliases, missing bytes, special files, links and drift refuse.
Excluded files are copied whole, capped at 2 GiB each, 8 GiB total and8192
objects, with private600 files/700 directories. The retention receipt binds
the full partition. Local readback verifies every object, mode and namespace;
the public receipt records only its store ID and receipt SHA256. Root must
separately retain this store and verify its availability/readback. The public
packet alone cannot rerun the normal comparator. Local retention is not a
remote storage guarantee or Root acceptance.

`run_transport_pair` is an optional Root-selected owned-executor adapter. It
requires the existing real Root capacity/runtime gate and actual run context
before callbacks. It preserves serial6900-second attempts, natural reaping,
twice-confirmed absence and strict comparison. Its concrete failure callback
exports only the available17 allowlisted comparison/log/provenance/proof roles
before caller cleanup, with 8 MiB per file and32 MiB total. Whole-byte overflows
or retention failures remain HOLD and preserve the primary failure through the
parent serial protocol. No arbitrary directory copy or raw exception text is
public. A failure receipt means all available allowlisted evidence was copied;
it never means a successful build. Postcollection observation failure removes
this invocation's success manifest so it cannot remain a stale PASS carrier.

`gui/` independently projects frozen recipe
`b05267833d497ef034576741bf31968019a526c3`, with its additional five modules.
It has separate recipe/parent locks, Source schema, checker and finisher.
Its builder refuses all actor entry. Its GUI seal, capacity and transport
remain UNBOUND; this F69 collector is not reused for GUI artifacts.
