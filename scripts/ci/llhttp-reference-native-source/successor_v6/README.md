# Strict inner public retention before cleanup

Source proposal only. Native95 remains failed/HOLD; its inner HOLD cause is
unproven. Retained public MOUNT_CLASS and owner status establish that Source,
root, `/tmp` and `/var/tmp` were read-only and work writable, and that the
payload returned HOLD without an exception diagnostic. They do not establish
why the held entry returned HOLD. Captured owner cleanup success is separate
from payload success and does not substitute for Root closure review.

The frozen Source93 controller requires natural payload success before copying
inner evidence. The held entry writes its public report, cleanup and retention
outputs on HOLD, but the controller skips their copy and destroys quota storage
during cleanup. This successor removes that success-gated recursive copy and
calls the strict public exporter in the actual controller `finally`, before
the unchanged cleanup. Payload success, pair checks, dependency checks, cleanup
and final PASS predicates remain unchanged. Snapshot refusal forces HOLD;
successful evidence export never upgrades a failed payload.

The exporter has 526 exact public paths and one manifest. It reads the held
entry's fixed report/cleanup/comparison/pair outputs, ten bootstrap public
receipts/logs, command000–159 JSON/stdout/stderr, and exact build1/build2 public
provenance, validation, locks, logs and the one llhttp XZ archive. Successful
payloads require the archive and mandatory public build receipts in each build;
missing files make the snapshot incomplete and preserve HOLD. A failed payload
may have only its report/cleanup and partial command logs, all retained as
nonaccepting DATA. Unknown filenames are never read. No recursive discovery,
cache bodies, Docker context, GPG homes, launch configuration or environment
dump is read. The inherited `environment.txt` is specifically uname, pagesize,
makepkg version and package inventory, as verified in the pinned builder.

Reads use directory capabilities and O_NOFOLLOW, reject links/nonregular files,
wrong ownership/device/modes and unstable or oversized files, and bind the inner
report to the exact Source/ref/map/run/attempt/job/nonce and original public
schema. The complete snapshot, including its manifest, stays within the
inherited16MiB evidence cap; the existing final15MiB encoder bound is unchanged.
No output is truncated. A refusal record contains only an allowlisted exception
class, message length and bounded prefix SHA256. The original cleanup is still
attempted after export refusal. No resources, time limits, package rules,
Root roles, domains, custody, zero-APT policy, Go address-space rule, source
read-only projection, signatures or retirement predicates are relaxed.

Source95 fits the unchanged strict less-than-96-file and 2MiB Source bounds.
It adds exactly two leaves: the exporter and a compact inverse record containing
the complete old controller, policy, program and Source map. It restores all93
parent bodies/modes and the complete85/76/68/62 inverse chain. The new policy
only adds the explicit public retention declaration. All other parent bytes,
including the held entry, remain identical. Family docs and tests are not
exported into the Source namespace. Every actual selector remains NULL.

Eleven actor-fenced controls cover actual public95 observations without cause
inference, exact HOLD retention surviving modeled storage removal, successful
snapshots without acceptance, missing success archives, no private reads,
context/schema/tamper/link/mode/UID/path/budget refusals, actual finally-prefix
execution with an injected export refusal and modeled cleanup, full95/93
inverse and unchanged protected controller functions/bounds. Ordinary files and
MODEL data do not establish a mounted namespace, native pair, signing,
installation, ARM16K/M2 compatibility, performance or release acceptance.
