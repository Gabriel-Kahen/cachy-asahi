# Future project TEST provider: separate successor required

This v18 helper accepts only original ALARM signatures under the unchanged
3098-byte public keyring and exact ALARM signer. A project key, freshly built
archive, edited `.BUILDINFO`, copied upstream recipe, or matching package name
cannot satisfy that path. Official recipe/source correspondence remains HOLD.

A future separately reviewed project provider needs this finite DATA interface:

- Exact project package archive, detached signature and public TEST key pins,
  full signer fingerprint and a separate explicit project trust declaration.
- Pinned project recipe and patches, source URLs/revisions/checksums, source
  license bytes, build commands, build environment/inventory and unedited
  `.BUILDINFO`; package metadata and exact regular ELF64 AArch64 library and
  symlink descriptors. Record actual native build results and the clean pair
  comparison separately from source audit.
- A complete signed350 baseline plus additions inventory. Preserve all existing
  versions and recipe dependencies, use Required signature checks and ordinary
  pacman dependency solving, refuse new scripts/hooks and archive path escapes.
- Host extraction and both existing cap0 qualifier observations for the same
  image, inventory, package ownership, provider modes/hashes/aliases and native
  `RTLD_NOW|RTLD_LOCAL` loads. Keep nine CLI probes and existing resource limits.

Use a new named policy/schema and dedicated verifier/context builder for this
provider; do not extend the ALARM signer allowlist or relabel TEST signatures as
official ALARM authentication. Its constructor must bind all bytes, preserve the
complete Source367 inverse and keep actual/acceptance/grant fields unissued
until Root separately reviews that exact successor. No such implementation,
trust grant, native build, load, installation or dispatch is issued by this note.
