## Rootfs digest scope

Source337's reported trial stopped after extraction when its host tree hash
reopened a restricted file and received EACCES; it produced no Rust build. The
actual failing file's mode/owner were not retained and remain unknown. Source340
changes only the bootstrap's fresh private host DATA extraction/hash/finalization
path. Content is hashed while staging remains readable, using original modes in
the unchanged canonical path/kind/mode/content row format. Exact final modes are
then applied once through checked descriptors, with identity/mode verification.
The completed extraction digest is reused instead of reopening restricted files.
This changes historical input provenance, not the native build root or resources.

The Reader requires exactly these extraction fields:

- `files`: integer1..600000; `logical_bytes`: integer0..16GiB.
- `digest_timing`: `PRIVATE_READABLE_STAGING_BEFORE_EXACT_MODE_FINALIZATION`.
- `final_modes_verified`: true.
- `rootfs_tree_sha256`: equal to both bootstrap and qualification digests.

The result preserves the original receipt as `input_rootfs_staging` and states
`input_rootfs_digest_scope=HOST_DATA_STAGING_PROVENANCE_ONLY_NO_POSTMODE_CONTENT_REHASH`.
This is no post-mode content rehash, atomic filesystem snapshot or image/rootfs
reconstruction. Image config/layer checks and actual stage0/LLVM qualification
remain separate guards; no new Rust1.99 runtime probe is implied.
