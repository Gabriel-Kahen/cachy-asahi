# Published LLVM256 compiler adapter

This successor joins the Rust native route to published LLVM Source
`365a763bc515a1b3550cc804536ddbf66353aac8`, ref
`refs/heads/codex/llvm23-source-reference-native-v2-20261115-r2`, and its
complete 256-file DATA identity. Root's actual complete public readback is
preserved as a byte-pinned static receipt. Publication does not supply a native
run, package, Reader result or Root acceptance.

The parent is the immutable 298-file v4 checkpoint, development commit
`7e1d4d6e5b0d8958bca755914b05fd190a4d0590`. This constructor verifies its
complete bytes, modes, membership, Source map and Git tree. It also verifies
the entire canonical LLVM256 Source as DATA. Only the LLVM declaration,
admission adapter, Source entry guard, workflow entry hashes and unadmitted
template may replace parent leaves. New Reader snapshots and a rejoin record
are separate leaves. A complete inverse restores Rust298. The earlier v4
constructor, profile, output and archived Reader remain unchanged.

Compiler source, recipe, flags, actor code, bootstrap, material delivery,
qualification, transfer, producer and resource limits are preserved. Both
workflow aliases still use the existing two-job route, with no protocol or
once-operator changes. The new marker distinguishes this successor from the
historical v4 checkpoint hold; no old receipt is rewritten as new evidence.

Independent Reader v4, development commit
`8f116d744126c1c87e6c030fde27d591ac921a54`, binds LLVM256 and verifies its full
256-to-253-to-251-to-248 inverse chain. Reader code is retained only as DATA;
this constructor and its controls never invoke a Reader or compiler. The
adapter requires an actual Reader binding and result joined into the same
Root-accepted Original/package/signature decision. Runtime qualification
cannot create that decision. Future run/job, Original, material, Reader result
and Root acceptance selectors remain NULL in the generated template.

Portable controls run in separate isolated Python processes on 3.12 and 3.14.
They demonstrate local construction, inverse and admission behavior. They do
not demonstrate acquisition, containers, stage0 execution, compilation,
installation, native 16K/M2, performance or release qualification. The inherited
Source/license, production-trust and hardware holds remain open.
