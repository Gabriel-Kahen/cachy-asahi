# Installed PipeWire AAC smoke source

`smoke.c` is original MIT-licensed test code. It takes one absolute installed plugin path, ordinarily `/usr/lib/spa-0.2/bluez5/libspa-codec-bluez5-aac.so`. It uses `dlopen(RTLD_NOW|RTLD_LOCAL)`, enumerates the AAC factory, checks the private SPA interface version16, and selects classic AAC-LC at48kHz/stereo/S16. Forty bounded PCM blocks pass through the shipped plugin's RTP/LATM encoder and decoder. PASS requires at least32 decoded packets, matching packet headers, complete consumption, expected PCM dimensions and nonzero output; lossy PCM is not required to equal input. State/properties/handle/library cleanup precedes the PASS line. The resolved `aacEncOpen` library path is reported separately so the caller can join it to transaction ownership/hash evidence.

Build with the installed PipeWire SPA development headers and these exact private headers:

```sh
cc -std=gnu11 -Wall -Wextra -Werror -I/runner/headers -I/usr/include/spa-0.2 /runner/smoke.c -ldl -lm -o /tmp/fdk-pipewire-smoke
```

No FDK development headers, Bluetooth daemon/device, audio device or PipeWire daemon are needed by this executable. The private interface is deliberately tied to PipeWire1.6.9; an ABI version mismatch refuses. The coordinator's local x86_64 compilation with the command above passed. Against the installed PipeWire1.6.9 plugin and host libfdk2.0.3, the smoke reported40 packets,40 decoded packets,163840 PCM bytes and nonzero output; a missing plugin refused at phase `plugin-dlopen`. These are local host checks. ARM execution remains NOT RUN, and independent review remains separate. The smoke tests generic codec consumption, not Bluetooth negotiation, system audio routing, xHE roundtrip, Asahi speaker protection, physical16KiB/M2 behavior or package lifecycle.
