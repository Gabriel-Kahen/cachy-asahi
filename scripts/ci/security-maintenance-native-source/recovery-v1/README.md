# Finite interrupted recovery Source proposal

This additive factory has exactly one parent: published Source
`850368889d6dcabdc8afbe87f64f05650c44f90a` (tree
`693c61dab8e3ae2383afc971a585b5236403435c`, sole parent
`ff8241ec2c73b69d6e54b8ee15209ef30760d619`). All 200 parent files, modes,
the nonrecursive 199-row map and raw commit are authenticated before rendering.
The existing sibling factory and its 200-file output contract stay intact.

The proposed successor contains 209 files / 208 map rows: nine new Python
modules, eleven changed old files including the derived map, and 189 held files.
Its proposed operation is `security-alpm-interrupted-recovery-v1`; actual Source,
ref, run, job and artifact selectors remain NULL. A prospective tree is a DATA
result, not a published commit or native receipt. Root owns construction,
publication, resource admission, native trials, original retrieval and matching
capsule Reader execution.

The producer first captures the exact 349-package baseline, performs a bounded
TEST-signed candidate warm install, captures its raw local database, removes it
and proves baseline restoration. It retains the original normal signed upgrade,
normal observer END and repeated install episode. A separate recovery episode
restores baseline, installs the signed prior package, blocks in the first real
upgrade-zero callback, verifies the descriptor checkpoint and snapshot, then
interrupts the reserved owned process with pidfd SIGKILL. Recovery accepts only
the specific empty new database directory, absent old/new payload union, and
zero-byte mode-000 stale lock shape. It removes those two exact objects, verifies
the signed candidate, installs it once, and checks the full resulting snapshot
and 350-package inventory. Other interrupted states fail closed.

Every effect has a durable hash-chained, fsynced command/phase journal. Partial
journals authorize no resume or retry. The native adapter binds process root,
root uid/gid, aarch64, exact Source/map and an owner-staged disposable-image
sentinel. It keeps fixed commands, private Required/Required pacman config,
one-day TEST signer/expiry checks, owned bounded processes and input pins.
Container/image provenance is still joined by the retained outer owner/Reader.

Reference and recovered ALPM metadata may differ only in the single decimal
`INSTALLDATE` value, each inside its actual owned install time window. All other
bytes, fields, order, unknown fields, files and package/payload entries must
match. This is supported by the retained libalpm manfile and local format
observation recorded in the development evidence; native reference bytes must
come from the exact target binary and candidate archive.

The passive recovery verifier is wired into the matching outer Reader, after
its existing Source, consumer, image and engine checks. Its sole new journey
sidecar is bounded to 8 MiB; the ordinary result remains 2 MiB, payload 16 MiB
and whole public/capsule bounds 32 MiB. It requires separate normal and recovery
evidence and positive recovery-prefix cleanup. It grants no Asahi/M2, native
16K, performance or Release acceptance. Upstream source/build correspondence
remains OPEN. The blocking C source has not been compiled or executed locally.

Focused tests use pure DATA, temporary files and explicit fake command
backends; owned-process tests use benign host Python children only. They do not
run real GPG, pacman, native code, compiler, network, capsule Reader or factory
emitter. The complete original 62 controls now execute against the current
modules, alongside all 99 new controls and four production-wiring/journal-failure
regressions: 165 distinct controls. Original source, tests and results remain
separate provenance under `controls/original62/`; cached results are not counted.
One private owned supervisor retires each worker and its descendants on failure.
Factory rendering and Source wiring use a separate actor-denied worker and
never invoke the immutable Source emitter.

From a maintained checkout, the new tests can be run with an authenticated
ordinary Source850 directory supplied as DATA:

```sh
python -I -B -Werror::ResourceWarning run_controls.py \
  --parent-source /absolute/Source850 \
  --results /absolute/fresh-results.json
```

Only Root may invoke the actual constructor. It requires a fresh output inside
a caller-owned 0700 directory and publishes with no-replace rename. Its inputs
are finite and pinned; it contains no package installation, network, Git,
publication or native actor. The two additive workflow steps run all 165
DATA/temporary/HOST controls under the retained Python 3.12 and 3.14 matrix.
Those future CI executions and the changed workflow body require their own
actual qualification; this proposal supplies no resource certificate.
