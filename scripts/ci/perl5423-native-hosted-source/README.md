# Proposed hosted Perl native Source

This directory constructs one closed Source proposal for the ordinary
`perl5423-native-pair-v2` route. It is source construction and actor-fenced DATA
validation only. No daemon, image build, native pair, upstream download,
publication, approval, Original GET, or operational Reader ran. Source/ref/run/
job/Reader/authority selectors remain NULL. Root owns publication and actual
roles after the kernel run.

The proposal holds two complete components unchanged: the 200-file Root-exported
Source3937 tree (`f1757dbedeed1591cdb8538f6c91e493cd451966`, 40,287,605 bytes)
under `original/`, and the 60-file v2 adapter/37-file packet under `perl/`.
The latter is pinned by component map
`3f238d649cb649ba2aff45e7930e49b28e3a7d8891860a1a17ead850719d5dee`.
Neither the old namespace owner nor its four-recipe main is invoked. Old
namespace metadata is historical DATA and cannot qualify Perl. No nested
namespace support is invoked or credited; private keys are not supplied.

## Concrete hosted route

1. Check out the exact future Root-published Source and verify every file/mode,
   complete Git HEAD/tree/blob membership, and both workflow aliases before any
   existing cache secrets are used. The new compound Source gets its own proof;
   old200 Git/workflow receipts are never spoofed.
2. Reuse the original 22 private cache chunks, pinned public14 seed, and exact
   original retained carrier transport. These are existing acquisition inputs;
   no new secret or upstream revision is introduced. A single bounded GitHub job
   metadata read uses the existing Actions token after Source proof to bind the
   actual numeric job ID. The token is never retained. This adds read-only
   `actions: read` to the proposed workflow permissions for Root to review.
3. Read actual local-daemon identity and resource/storage observations. Use the
   held original input contract, full-carrier preparation, fixed-eight cache
   copies, package-cache fetch policy, and original base-five acquisition path.
   Call unchanged `native_arm.audit(combined)` and `build(combined, ..., {})` for
   **one** fresh signed349 image. This is 256 package archives plus the signed
   rootfs: 517 acquisition files and 257 signature results. Public fingerprints,
   full package metadata, Required ALPM signatures, disabled hooks/scriptlets,
   and exact349 inventory remain mandatory.
4. Bind the resulting immutable image, actual Source readback, native-daemon
   observation, signature audit, Source/run/job and external Root approval into
   the v2 admission operands. Invoke the held ordinary pair directly in the main
   coordinator process, preserving its complete 6,000-second pair contract and
   two full 2,400-second builds. This avoids wrapping a 6,000-second pair with a
   child helper whose single-command maximum is 3,600 seconds.
5. Independently attempt host GPG-agent retirement, exact named inventory-probe
   retirement, and exact owned image retirement. No foreign image tag, shared
   image, unnamed container, or daemon-wide cleanup is permitted. Failures are
   aggregated; one failed cleanup does not silently skip the others. Only the
   explicit public audit/pair paths are uploaded. Cache, rootfs/context trees,
   host GNUPG homes, image-private keys, and credential values are excluded.

The new wrapper changes callback seams, not the held helper files. Original
`owner.cache_file` handles the original packages, including 104 MB/68 MB inputs;
the 64 MiB `checked_file` helper is used only for the fixed eight. GPG and native
CLI operations retain separate raw stdout/stderr and natural direct-wait/group
retirement evidence. The retained-carrier helper keeps its exact large-blob
selection policy. Cancellation is forwarded at its owned primitive boundary,
after the blob cap has been selected and child ownership exists, and all scoped
function/import overrides are restored.

An approval digest is a binding identifier, not proof of authority. Root must
authenticate Source, approval, once-role, daemon, resource and trust admission
outside this code before any actual invocation. This proposal creates none.

## Daemon requirements and blockers

The initial hosted profile uses the **existing local rootful Docker daemon** at
`unix:///var/run/docker.sock`. The v2 adapter's “rootless” premise describes the
UID1001/cap0 build container; it does not require rootless dockerd. Rootful is
compatible in principle with the fixed socket and CHOWN-only volume initializer.
Actual compatibility is unobserved here.

The entry requires native Linux ARM host/server, coordinator UID/GID1001, stable
root-owned local socket, a known unremapped/rootful security profile, cgroup-v2
CPU/memory/swap/PID support, and canonical accessible DockerRootDir. Docker
storage need not belong to the runner. The actual DockerRootDir and all four
temp/work/cache/carrier paths must have fixed inode counters, 120,000 available
inodes and an 8 GiB free-space admission reserve; input storage is observed
before seeding. Each actual filesystem is checked; free space is not summed
across duplicate observations of one device. Host MemAvailable must be at least
8 GiB. The adapter still performs its own seven capacity gates and actual
create/inspect/entry/runtime enforcement checks after image preparation.

Inaccessible or aliased DockerRootDir, unavailable cgroup enforcement, unknown
inode pools, wrong identity, or insufficient resources cause HOLD. There is no
daemon launch, rootless substitution, `--userns=host`, permission change, policy
relaxation, or privileged fallback. Image preparation uses the ordinary daemon
and needs separate Root resource admission; pair-container limits do not bound
the Docker image-build stage.

If a Docker build is forced or fails before terminal daemon proof, the wrapper
attempts recovery using the deterministic Source/token image label and exact
tag, but records daemon-build retirement as UNPROVEN and keeps FAIL/HOLD. Image
absence at one instant does not establish that daemon-side build work finished.
The normal PASS path requires natural command retirement and exact final
container/GPG/image absence. No actual admission or retirement result is claimed
by these Source controls.

## Workflow and time budget

The emitted `.github/workflows/native-arm-build.yml` and new
`.github/workflows/native-arm-perl5423-v2.yml` are byte-identical. Their only
operation is `perl5423-native-pair-v2`, on the existing ARM runner label, with
`native-arm-build`, `cancel-in-progress: false`, and `queue: max`. No shared
repository workflow or manifest is changed by this package.

The job timeout is **225 minutes**. Declared step maxima total 207 minutes. The
185-minute native step fits 4,500 seconds for signed349 preparation/build,
6,000 seconds for the full pair, and 240 seconds for bootstrap resource cleanup
(10,740 seconds total). The pair includes its own 180-second cleanup reserve.
The outer native timeout and termination grace also fit within the step. These
are finite limits, not measurements or a guarantee a future run will pass.

## Independent Reader and transport

`hosted/reader_entry.py` is a separate future Root-admitted entry. It requires
qualified Python 3.14 zstd support; the runner label/default Python is not proof
of that runtime. Reader execution is not automatic in the native job.

The independent wrapper verifies the whole Source and held component maps,
actual Git/daemon/storage receipts, all 517 acquisitions, all 257 actual GPG
results and raw streams, exact349 inventory, owned bootstrap build/cleanup, and
v2 admission bindings before delegating to the immediately pinned Perl Reader.
The held Perl Reader still checks full harness/runtime/provider/archive and
reproducibility evidence. Neither wrapper imports collected artifacts as code.

For retained evidence at a different physical path, two explicit read-only I/O
seams map the observed native pair root to the retained directory: held
`read` and `export_namespace` calls. Their original bounded no-follow/file/mode
checks run unchanged, and all capacity/inspect/native-path decisions keep the
original logical paths. The functions are restored even on refusal. Raw bytes,
metadata and decisions are not rewritten. Git proof argv likewise binds one
observed native Source path, while Source bytes are checked at the Reader's
physical Source location. The verdict declares this transport view.

## Construction and validation

`prepare.py` verifies the exact complete no-Git Source export and v2 component,
adds only the pinned hosted payload/new aliases, and emits a complete Source map
and exact inverse. Removing its listed additions restores all 260 held byte/mode
identities and their virtual tree. The pinned filesystem helper is unchanged;
its readback file-count limit is scoped to 320 for this compound Source and
restored afterward. Components retain their original bounds. Construction has
no Git, network, daemon, compiler, native or operational Reader dispatch.

Root can review the DATA-only constructor invocation:

```sh
python3 -I -B scripts/ci/perl5423-native-hosted-source/prepare.py \
  --original-source /ROOT/READ_ONLY_ORIGINAL3937_EXPORT \
  --packet /ROOT/EXACT_37_FILE_PACKET \
  --profile-sha256 ROOT_REVIEWED_PROFILE_SHA256 \
  --output /ROOT/PRIVATE_PARENT/FRESH_SOURCE_DATA
```

`profile.json` pins every input and payload; `validation.json` records current
map/tree identities, bounded Source construction and actor-fenced controls.
Fixtures are synthetic or read-only frozen metadata, never native results.
Native Perl, installed ABI/external XS, 16K/M2, performance, production trust and
release acceptance remain unqualified.
