# Mirror native package context

Exactly `cachy-asahi-mirrors` 0.2.0-2; no shared inventory changes. Testing uses
a local controlled snapshot and private loopback TLS CA. No public mirror trust,
ranking-performance, M2, 16K, power-loss, release or maintenance claim follows.

`prepare.py --source /absolute/repository --output /absolute/new-context` creates
a closed destination-ready source tree and sibling checksum authorization JSON.
It verifies twelve pinned producer/build/preservation helpers, the six current
recipe files and all lane sources. It freezes a new explicit workflow and its
job/manifest checksums; it creates no canonical workflow alias. All actual
source/ref/run selectors stay null. Default candidate_source is also null, which
fails source proof before secrets or actors. Root later adds
`--package-source EXACT40HEX` to bind six published recipe Git-byte joins, then
publishes and dispatches the explicit workflow/source revision. No Git mutation
or dispatch happens during preparation.

The manual workflow reuses the exact maintained574 producer, existing six private
retained inputs and fourteen public ARM inputs. Existing secret chunks are never
printed or exported. The source/workflow SHA must match and the runner, daemon
and image must all be native ARM. No new package fetch route is introduced.
Two distinct read-only clean makepkg actors run all31 product checks and bind
generated metadata, exact four-file MIT payload, archive bytes, contents,
PKGINFO and BUILDINFO. Actual page size is recorded rather than inferred.

One disposable root actor performs install → same-version reinstall → remove →
reinstall after removal → final remove, requiring exact575/574 inventories,
ownership and payload. It preserves both fixture homes, previous fixture outputs,
and original system mirror/pacman files. Hooks are masked inside that root only.
Only this actor gets the original six filesystem/UID capabilities; each installed
CLI suite runs as ordinary alarm in fresh/existing homes. The lane does not
certify every original574 payload file, beyond inventory and named protected files.

Before ALPM installation, both ordinary users also run that same suite on four
data-staged payload files bound byte-for-byte to the verified build-A archive.
This is data staging, separately recorded from package installation.

Each CLI suite runs real loopback TLS exact/mismatched/all-failed ranking, binary
original-byte and POSIX metadata restore, absent-target restoration, idempotence,
six recovery paths and active/pending user-edit refusal. Nine genuine SIGKILL
children stop at AST-bound durable boundaries in the unmodified CLI main under
a Python line trace; parent observes SIGSTOP, kills and reaps, then an ordinary
command recovers. Ordinary calls invoke the staged/installed executable directly.
This is process interruption evidence, not storage power-loss evidence.

The complete consumer set is one probe +two builders +one lifecycle. An exclusive
lease and source/run-bound labels protect cleanup. Names persist before launch;
cleanup verifies name/image/label/actual ID, removes only that confirmed ID in
reverse order, verifies absence, then retires the producer. Foreign or unknown
state fails cleanup and preserves the producer. Limits: consumer2350s,
build240s each, lifecycle600s, producer2300s, cleanup330s, plus explicit workflow
and output bounds inherited from the producer lane.

Only the closed public directory is uploaded, capped at192MiB and three days.
It contains source/license files, proof, both archives, build metadata/logs,
fixture-only lifecycle receipt and ordered cleanup. Per-file caps apply. Private
CA keys, raw journals/original bytes, transcripts, HOME trees, dependency inputs,
caches and layers stay out of public retention. TLS keys are removed after use;
other private fixtures remain in the owned root until container retirement.
Partial source/pair/lifecycle/retention/cleanup cannot earn native acceptance.

Host checks do not need native inputs or change host configuration:

```sh
MIRRORS_NATIVE_SOURCE=/absolute/repository python -B -m unittest discover \
  -s scripts/ci/mirrors-native -p 'test_*.py'
python -B scripts/ci/mirrors-native/host_stage.py --source /absolute/repository \
  --output /absolute/new-host-evidence
```

The staging command runs the actual recipe package() into a fresh private tree,
verifies exactly four payload files/modes/hash joins, runs all31 product checks,
and exercises that staged executable through the complete CLI suite. This proves
host staging and real CLI behavior, not clean makepkg pairs or ALPM installation.
