# Docker28.0.4 OOM default comparison

The actual d7 run failed guest import before reaching bwrap. All four retained before/after HostConfig records also differ solely at `OomKillDisable`: false before start, null after exit. The original strict reader qualified diagnostic DATA with UNKNOWN namespace interpretation. This correction does not reinterpret or replay that capsule.

Moby v28.0.4 [creation](https://github.com/moby/moby/blob/v28.0.4/daemon/create.go#L75) verifies settings before adapting defaults. Its [default adapter](https://github.com/moby/moby/blob/v28.0.4/daemon/daemon_unix.go#L375) changes an absent OOM-disable pointer to false. [Start](https://github.com/moby/moby/blob/v28.0.4/daemon/start.go#L64) verifies settings again; [unsupported OOM-disable handling](https://github.com/moby/moby/blob/v28.0.4/daemon/daemon_unix.go#L468) clears the pointer. Only a true discarded value produces a warning. The [CLI](https://github.com/docker/cli/blob/v28.0.4/cli/command/container/opts.go#L603) supplies a pointer to its false default. [OCI runtime-spec v1.2.0](https://github.com/opencontainers/runtime-spec/blob/v1.2.0/config-linux.md#memory) defines false and the omitted default as OOM killer enabled. Moby's [resource-to-OCI mapping](https://github.com/moby/moby/blob/v28.0.4/daemon/daemon_unix.go#L105) forwards only non-null pointers. This supports the narrow default-representation comparison, not a policy relaxation.

`host_config_default_v1` requires identical complete key sets, created value exactly false, and type-exact equality of every other field recursively. Unchanged false is exact. False to null additionally requires Engine version exactly `28.0.4`; true, integers, missing keys, reverse transition, different versions, and every unrelated resource/security delta are refused.

The 22423-byte frozen core and contract stay exact. An additive wrapper first validates the raw pair, then supplies an internal comparison view to the frozen validator. The retained result, raw inspection logs, their pins, and runtime role/body/ownership inverses remain unchanged. Owner diagnostic and reader qualification explicitly record the predicate and affected case IDs. The matching reader recomputes the comparison from raw-joined records and rejects a fabricated owner marker. No capsule marker grants permission by itself.

Three new DATA tests cover exact positives/refusals, all-four synthetic owner and matching-reader integration with raw bytes unchanged, and marker/raw-resource forgery. The isolated-launch test uses newly authored inert modules, not an actual guest or old capsule. New actual namespace evidence remains NOT_RUN.
