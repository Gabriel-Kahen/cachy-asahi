# Fish Done generic 16 KiB recorder trial

Separate manual diagnostic lane. Source implementation and inert controls do not
establish runtime success. Root owns integration, exact commit/workflow/manifest
freeze and actual CI. This worker runs no compiler, Docker container, VM, product
PTY driver, package installation or real notification actor.

The lane maps the twelve adopted `cachy-asahi-fish-done` 0.1.0-2 recipe sources and exactly
eight package payload files plus the existing eighteen-case driver. Every file has
an explicit source/destination/mode/byte/SHA256 binding, with upstream/project
licenses and notices retained. The guest reports
`NOT_INSTALLED_EXACT_SOURCE_PAYLOADS_COPIED_ONLY`; there is no pacman registration
or native package claim. Root's native package and installed lifecycle are separate.

The existing offline owned574 producer, six secret-seeded inputs and fourteen-file
public seed are reused unchanged. Its inventory SHA256 is
`cfd4c76f8602164c1091aed121332d201d0bf9299d3a51aedfb67f79c834e0ac`, including Fish
4.9.3-1. There is no new guest userspace/Rust/audio build or input download.

Read-only ordinary-user capture verifies inventory before/after, drops all
capabilities, requires no-new-privileges and no network, and imports definitions
only. It copies exact product/driver bytes, native Python sources/imported
extensions, Fish/resources, xterm terminfo and finite init/test tools including
sleep/sh/timeout/kill. Full ELF interpreter/DT_NEEDED closure is required; every
ELF must be AArch64 and structurally 16-KiB aligned. No real notify-send binary,
notification manager, desktop, D-Bus service or socket is copied. Limits are
4,096 files, 256 MiB total, 64 MiB/member, 270 MiB private tar, 1 MiB receipt,
240-second capture, 128 processes and 2 GiB memory.

The kernel uses the existing source-pinned
`scripts/ci/tools-generic16k/build_kernel.py`, SHA256
`c6ae177cb7487d86bcdd428994ce0ae3ccf5375262da622cd4bd27f9564758e5`, and its
unchanged base fragment SHA256
`6d91180b80138d2d8039efafaaa9ca31349baea22b90430cbb15e07bce02e8f6`.
They are copied to this job's private work directory, without editing either
accepted lane. The existing profile `TOOLS16K_PTY_DERIVED_DIAGNOSTIC` adds only
UNIX98 PTY support to the original accepted diagnostic configuration. Actual
helper/base/derived fragment, Image/config, modules-disabled and 16-KiB page
checks remain mandatory. Original source license, tool, 3,600-second build and
16-GiB workspace records remain intact.

Acquisition uses the identical bounded direct transport helper from the separate
four-tool HTTP429 correction: two declared codeload tag aliases, once each,
no redirects or proxies, normal TLS verification and a shared 300-second hard
deadline. Only transient failures allow the second URL after one pause capped
at10 seconds. The unchanged pinned fetch reader still requires all 262,965,559
bytes and SHA256
`874ef68d04ac8c831b90bb01a387cfabb58fceb60842c49a0d0e58bcd6c146ad` for Asahi
revision `94fb23346d522edf53722357c426a3e58030beea` before publication; the
unchanged builder verifies again before extraction. Original manifest/evidence
and authentication limits are retained in a <=16-KiB attempt receipt. Alias
content differences fail; there is no commit-archive/hash substitution, signature
waiver or claimed avoidance of a future throttle.

The diskless guest uses TCG, one CPU, 1 GiB memory, no network/display/monitor,
600 seconds and 1 MiB UART. Private proc/devtmpfs/devpts and fixed synthetic
passwd/group/nsswitch entries serve the fixture only. Init requires actual uname,
getconf and the unchanged mmap/mprotect/file-offset probe to agree with aarch64,
the exact kernel release and 16,384-byte pages. Python checks actual sysconf too.

After the marker/page guard, the guest drops supplementary groups and UID/GID to
23001. One bounded 240-second outer command runs the unchanged adopted driver
against the mapped module. All eighteen cases must pass: noninteractive no-op;
foreground success/failure/short/exclusion/invalid setting; watched background
success/failure/SIGTERM/rejection/disown/disable; repeat and caller continuation;
existing keys/handlers/namespaces/autoload; literal opt-in command text; missing
bus/dependency; transport failure and forced timeout. Expected status, default
private notification body, exact notify-send arguments, escaped opt-in text and
transport elapsed time are replayed by the controller. The driver's executable
local recorder receives a deliberately nonexistent bus address; it never connects
to a real notification service. No display or notification delivery credit is given.

The outer command records natural expected exit, bounded stdout/stderr and full
group absence. No other UID-23001 process, including nested PTY/job/recorder groups,
may remain. All eighteen private configuration/history inputs must retain exact
bytes, caller UID/GID, single regular inode link and 0600 mode. Existing HOME/XDG
sentinels and every captured product/source payload are verified before/after.
The receipt's legacy case labels do not establish installed-package acceptance.

Capture, static page-probe compile and QEMU each keep an unreaped session leader
through cleanup signals and require natural exit plus group absence. The guest
report must have one nonce-bound ordered marker sequence, all eighteen cases,
source hashes and scope limits. Panic, timeout, wrong pages, omitted cases,
changed input, real transport or leaked processes cannot produce PASS.

Consumer cleanup joins capture CID/name/image/job label, exports bounded log
tails, removes private files and proves the borrowed producer remains intact.
Only after the original producer proves probe/image absence may finalize remove
the completed owned `$RUNNER_TEMP/done16k-kernel` workspace and report
`PASS_GENERIC_16K_FISH_DONE_RECORDER_PTY_ONLY`. Interrupted/failed kernel work
may remain for disposable-runner cleanup and cannot yield PASS, matching the
existing helper. This does not improve active kernel build cancellation.

The workflow has its own concurrency group and exact source_sha/manifest_sha256
inputs, with source/workflow identity and source hashes checked before secrets.
Only bounded 2-MiB runtime metadata, including the acquisition receipt on failure,
is uploaded for three days. No package, key, executable, rootfs, initramfs or
private user file is uploaded. No automation is scheduled.

Inert controls forbid live network/subprocess actors. They check source/map drift,
archive substitution, complete ELF/page closure, kernel profile provenance,
status/privacy/timeout report replay, input preservation, host/guest guards,
finite session retirement and foreign cleanup refusal. Actual kernel acquisition,
build/capture/guest, native package lifecycle, Asahi/M2 hardware, performance and
release admission remain unrun by this worker.
