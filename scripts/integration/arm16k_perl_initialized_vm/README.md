# Opt-in initialized Perl baseline qualification component

Implemented readonly scan, input qualification, fixed SSH emptiness aggregate,
and exact initialized-state preservation. No new actor/controller/executor,
package inputs, platform stack, Root grant or lifecycle acceptance. Existing
`arm16k_perl5423_vm` (Source65) and its default cold-absence gates are unchanged.

The operational delta is explicit: initialized public9 nodes are required to
exist with the actual r72 types/modes, and may never be removed, recreated,
rounded, timestamp-repaired or silently waived. Each selected public inode's
bytes/target, size, inode, links, mode/owner/xattrs and mtime/ns are captured and
required equal before/after. Exact `etc`, `etc/audit`, `etc/udev`, `root` parent
metadata and existing empty `root/.ssh` metadata are also required equal.
The unchanged Source65 complete ALPM/payload/user/database preservation and
strict preboot parent predicates run first. Only its already declared normal
ALPM comparisons remain; the new selected nodes/parents have stricter equality.

`ssh_empty.py` reads one selected root-owned0700 directory's entry metadata,
not its children. It validates only unique exact dot/dotdot entries. Any other
live entry returns a fixed no-name negative aggregate without visiting that
inode or any body. Empty requires complete bounded coverage, links2 and stable
inode metadata. Bounds64KiB and8192 headers; no file-body chunks, symlink text,
xattr values or names are retained. Its private frozen counterpart was used by
Root's literal r74 proof. The r74 metadata demonstrates4096 bytes,3 headers
including one inactive record,2 live dot entries,0 other entries and no child
inode/name/value access. It does not qualify the full initialized baseline.

`scanner.py` composes the pinned Source65 frozen reader and ALPM/log parsing
with this new guard. It requires the actual proof/complete Root closure pinned
to raw f30, then independently rechecks the same selected empty inode before
inventory. Before that check, xattr reads are disabled. Inventory receives only
the exact entry blocks already verified empty, so even a malformed concurrent
input cannot enqueue a new SSH child. Full raw SHA/stat before/after rejects any
input change. Full namespace and public ALPM text remain authenticated by the
same bounded reader. This guard does not weaken or replace any Source65 method.

`observer.py` uses the existing readonly observer pattern to write bounded
namespace, paired ALPM records, ownership, full scan DATA, initialized snapshot
and an observation receipt. It emits no certificate or grant. Root must provide
a fresh explicit `scan-authority.TEMPLATE.json` instance, whole new Source pin,
whole immutable Source65 lock, actual r74 proof/closure, runtime binding and
existing external memory/CPU/PID/quota/output/custody enforcement. Default NULLs
refuse before raw access. Root executes the observer under its established
bounded limiter/controller; this Source does not create scopes or containers.
`next-operation.TEMPLATE.json` contains the concrete fixed next invocation and
fresh selectors. The earlier16KiB/120s stat grant cannot authorize the larger
complete namespace observation; it needs a separate Root operation/enforcement.

`qualification.py` then requires a newly Root-bound complete scan certificate
and all six existing Source65 evidence roles. It verifies the complete stable
namespace pin, complete111-package ALPM ownership, actual provider bytes/mode/
owner/aliases, exact initialized snapshot, and genuine Source65 `validate`
package/signature/dependency/ELF/resource/recovery gates. Raw/prepared must be
f30/04923...; cold certificates and r72 presence-only evidence reject. The Perl
archive/signature/public TEST certificate/receipt, native tuple, signer and
original validity window are frozen. Actor/guest/resource bounds remain exact;
only actual warmed allocation/free geometry and fresh Root metadata may differ.
No actual resource availability, timestamp, Root approval or output is invented.

The observed complete namespace must precede new Root baseline/runtime/resource/
input-decision certificates. Both templates leave those selections NULL. The
qualifier returns DATA-only validation with Root/VM/Perl/hardware/release
acceptance unset. There is no automatic certificate minting or package install.

Remaining work: actual initialized full observation; independent Root review
and new certificate tuple; a separate opt-in initialized fixture/context producer
and guest integration which never runs cold absent-path cleanup on present
nodes; then fresh exact lifecycle execution under the existing Root framework.
The old Source65 actor and cold preboot/root-SSH descriptors still refuse this
baseline and must not be reused. Case14 remains consumed HOLD. Native, M2,

Validation is Source/MODEL only: synthetic empty/nonempty/header/privacy controls;
exact public9 inode/content/metadata and parent/SSH preservation mutations;
genuine unchanged Source65 ALPM ownership/provider and preservation functions;
verified r74 metadata binding and r72/cold refusal; no-private-child inventory
race model; unissued-declaration refusal. No actual raw image, credential,
