# Disposable Apps transactions

`transaction.py` is a separate execution backend for the existing signed Apps planner. It mutates only a fresh copy that this backend prepared beneath a private workspace. It cannot target `/`, accept an arbitrary live root, invoke automatic repositories/fetches, or enable hooks/scriptlets. The existing runtime authentication helpers are unchanged.

Execution requires uid/euid0 inside a single-user mapped namespace or explicitly tokened disposable container, only the loopback network interface, `PATH=/usr/bin:/bin`, no loader/GPG/ALPM/pacman environment overrides, and an owner token in `CACHY_ASAHI_APPS_TRANSACTION` (32 lowercase hex digits). A real container must also be network isolated. Root paths and source parents must be canonical without aliases, and the workspace parent must be owned0700. The owner must exclude other actors from this workspace.

Supply `--apps-source` pointing to the exact installed or source Apps runtime directory, its externally pinned `--apps-provenance-sha256`, and `--repository-source` for the exact three-helper runtime tree. The provenance pin binds Apps code, inventory reader, entrypoint and helper pins before import. Signed native release provenance is required for nonsynthetic releases; those transactions run only on aarch64. Synthetic any-package tests may run on x86_64 with the existing pinned ALPM ABI.

1. Run `prepare-copy --source SEED --workspace FRESH_WORKSPACE` with the three source options above. It refuses `/`, overlapping roots, existing workspaces, locked/malformed ALPM databases, unsupported nodes/links/auxiliaries and insufficient byte/inode capacity. The original complete copier preserves the seed and verifies the copy. The output binds the exact workspace/root inode identities, owner token and four complete before digests.
2. Use the unchanged Apps `inventory` command against `WORKSPACE/root/var/lib/pacman`, writing outside the target root. Then use Apps' signed `plan install APP...`, `plan remove APP...`, or explicit `plan reinstall APP...` with that inventory and explicit release/catalog/keyring/signer pins. Save the original complete canonical planner JSON, including its binding and helper pins.
3. Invoke `transaction.py apply` with the source options, `--workspace`, `--ownership-sha256`, original signed-planner credential options, `--operation install|remove|reinstall --applications APP...`, `--plan PLAN --plan-sha256 SHA`, all four `--before-{tree,database,packages,inventory}-sha256` pins, and `--confirm-disposable-transaction`. `inspect` can refresh the four before pins for another explicitly planned transaction in the same owned copy.
4. After inspecting results and stopping all actors, invoke `dispose-copy` with the owner/source options. It removes only the exact prepared workspace via the existing descriptor-relative copier cleanup. An existing ALPM lock refuses disposal; it is never deleted as a stale-lock workaround. Discard the outer disposable container after a killed worker/lock uncertainty.

The default `apply` CLI supervises a fresh worker process group for300 seconds with1MiB bounded stdout/stderr; it naturally reaps the leader and retires the group. Direct Python `apply()` is for an already supervised owner. `prepare-copy`, `inspect` and disposal use bounded filesystem deadlines. No daemon, privilege escalator or production installer is introduced.

The backend copies at most32MiB of selected release input into a private workspace, then reauthenticates the exact signed release, catalog and external public keyring through Apps. It collects the actual copied ALPM9 database, binds its full record and package hashes plus the full root node/content snapshot, and regenerates byte-for-byte the caller's complete Apps plan. Ordinary ALPM signature, dependency, conflict and database locking checks remain active. Prepared add/remove sets must exactly equal that plan. No sync database is registered and no dependency/orphan/remove expansion is permitted.

All signed-base/protected package names remain immutable. Existing platform/trust/service/hook path guards apply to selected payloads. This first transaction policy accepts only ordinary non-setid `usr/` payload files/directories, with explicit existing/archive parents; scriptlets, hooks, backup/pacsave behavior, selected hardlinks, symlink ancestors, unowned collisions and special nodes refuse. Full-root hardlink groups belonging to the base are preserved through the existing projection and observation APIs. After commit, normalized package metadata must exactly equal the plan, all installed payload bytes/modes/owners must equal authenticated archives, removed owned files must be absent, and unselected payload/database/trust/user nodes must remain identical. Package-owned empty-directory removal is allowed only for selected paths; unrelated nodes remain exact.

An exclusive pending marker starts before ALPM mutation and is removed only after complete success/cleanup. A failed/uncertain attempt is not automatically retried. Interrupted commits report UNKNOWN when appropriate and never claim rollback. The root remains owned and disposable for inspection; temporary authenticated inputs, public keyrings, handles and normal transaction locks are cleaned by their owners.

Bounds retain the existing full-root defaults:587 packages,500000 nodes,8GiB logical root bytes,1GiB/file,100000 ALPM paths/package,300-second observation/worker deadline. The existing Apps collector also retains its4096-package/4MiB-record/64MiB-raw/16MiB-output/30-second guards; the tighter backend package limit applies. Archive parsing retains the narrow8MiB gzip/xz archive/128MiB aggregate decoded/20000-member guards. Copy reservation is tightened from the measured seed plus those existing archive/database growth bounds; precommit repeats measured free-space/inode and projected node/byte checks. Bounds are never silently raised or truncation used.

The dedicated [original574 closure](FULL574.md) now supports the exact four current script/data tools through explicit pinned policy and native extraction lease operands. It preserves the original574 tree and raw loader-cache bytes without executing ldconfig. The general full-root/copy APIs retain their strict defaults, and the separate Setup3→4 grant is unchanged. Actual original574 native transactions remain pending; this source implementation does not establish that composition. Likewise xattrs/ACLs, target hardware, desktop notification delivery, release freshness/antirollback admission and stable installation are not established by this development backend. Successful synthetic fixtures establish only the labelled copied-root transaction behavior.

Explicit `--operation reinstall` is supported with the Apps same-version repair plan. It performs ordinary signed same-version adds for precisely the `reinstalls` targets; metadata must already equal the authenticated release and no dependency expansion/removal is permitted. A damaged selected ordinary payload or missing selected regular-file leaf with an existing ordinary parent can be replaced; wrong types, missing directories and selected hardlinks refuse. target root observations/plan/input pins still bind the actual damaged state before commit. Postcommit requires exact signed payload bytes and unchanged metadata/unselected/base/user/trust bytes. Existing install/remove plans and behavior remain unchanged. Hooks/scriptlets, backups, selected hardlinks, aliases/setid/platform paths and unknown states remain refused; no overwrite/nodeps flag or automatic rollback is introduced. This remains development owned-copy authority, never a live-host repair entrypoint.

Scope limit: the separate leased-original574 adapter still requires exact current candidate payload bytes even before selection. Corrupted-candidate repair with that adapter is refused, not bypassed; only the generic copied-root path supports the damaged-payload repair exercised here. Current/historical native packets and their Apps5 identities must stay independently bound.
